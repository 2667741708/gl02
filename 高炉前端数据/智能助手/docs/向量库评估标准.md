# 向量库评估标准

更新时间：2026-05-09

## 1. 评估目标

本标准用于评估 8092 智能助手在对话框中调用“炉况执行引擎 + 高炉向量知识库”时的实际效果。

评估对象包括：

- 向量库检索是否命中正确知识类别和来源文档。
- 对话框回答是否正确使用检索证据。
- 回答是否结合当前炉况执行引擎的实时快照、诊断结论和数据质量边界。
- 回答是否符合高炉现场安全边界，不编造数据、不直接下操作指令、不武断认定唯一主因。
- 回答是否适合工艺问答、工况诊断、参数优化、运行报告和案例复盘等不同任务。

## 2. 固定评估指令

当需要做完整对话框评测时，应生成一份 Markdown 报告，至少包含 100 条可在 8092 对话框中直接使用的问题。

每条问题必须包含：

- 问题编号。
- 问题类型。
- 对话框实际提问。
- 理论标准答案方案。
- `220.12` 实际大模型回答。
- 自动评分。
- 评分说明。
- 调用状态和耗时。

每个对话框问题建议统一采用以下形式，便于控制输出长度和人工核查：

```text
请结合当前炉况执行引擎和向量知识库，控制在150字以内回答：{原始问题}
```

## 3. 100 条对话框评测集要求

100 条问题应按类型覆盖：

| 类型 | 建议数量 | 重点 |
|---|---:|---|
| 工艺知识问答 | 20 | 概念、机理、术语、工程理解 |
| 工况诊断分析 | 25 | 压差、风量、透气性、顶温、铁水硅、炉凉、偏行 |
| 参数优化建议 | 20 | 喷煤、富氧、风温、燃料比、提产、焦炭质量 |
| 运行报告表达 | 15 | 班报、日报、领导汇报、原因初判、后续关注 |
| 口语化/模糊问法 | 10 | 炉子不顺、顶温乱、想多喷点煤等现场说法 |
| 类案例与复盘问法 | 10 | 相似经验、异常复盘、适用边界 |

当前标准测试集：

```text
高炉前端数据/智能助手/tests/bf_rag_100_questions.json
```

## 4. 标准答案制定原则

理论标准答案不是要求模型逐字一致，而是提供人工核查用的“答案要点”。

标准答案应遵循：

- 定义类问题优先给稳健、通用、低争议解释。
- 诊断类问题必须体现“趋势性判断 + 依据 + 可能原因 + 补充信息”。
- 参数优化类问题必须体现“目标 + 核查因素 + 建议方向 + 风险 + 监测项”。
- 报告类问题不得补充用户未提供的数值、变化幅度、时间长度或检测结果。
- 案例类问题在真实案例库未结构化前，只能做相近知识类比，不能假装已召回真实事故案例。
- 涉及当前炉况时，应说明数据来源、诊断引擎结论和数据质量边界。

## 5. 自动评分口径

自动评分为初筛，不替代人工专家判断。

建议按 100 分制：

| 维度 | 分值 | 说明 |
|---|---:|---|
| 知识要点命中 | 50 | 是否覆盖标准答案关键词和核心机理 |
| 边界与安全表达 | 30 | 是否避免绝对化、编造数值、直接下操作指令 |
| 当前炉况结合 | 20 | 是否结合炉况执行引擎、实时快照、诊断或数据质量说明 |

高风险扣分项：

- 使用“确定是”“一定是”“唯一主因就是”等武断表述。
- 编造未提供的数值、阈值、报警线、时间长度或检测结果。
- 直接给出现场操作指令或具体调整幅度。
- 把 Open WebUI/8092 当前数据质量仍需核对的试接入数据当作已确认生产依据。
- 对报告类问题补充用户未提供事实。

## 6. 推荐运行命令

在本地项目根目录执行：

```powershell
$env:PYTHONIOENCODING = "utf-8"
$env:PYTHONUTF8 = "1"

python ".\高炉前端数据\智能助手\backend\run_bf_dialog_eval_100.py" `
  --limit 100 `
  --timeout 150 `
  --sleep 0.1 `
  --resume
```

默认调用地址：

```text
http://10.30.220.12:8092/api/qa/chat
```

默认输出：

```text
高炉前端数据/智能助手/tests/bf_dialog_eval_100_results.json
高炉前端数据/智能助手/docs/高炉向量库对话框评测报告_100条.md
```

如果需要在 8092 会话列表里创建一条专用于人工观察的连续对话，应使用：

```powershell
python ".\高炉前端数据\智能助手\backend\run_bf_dialog_eval_100.py" `
  --limit 100 `
  --timeout 180 `
  --sleep 0.1 `
  --dedicated-conversation `
  --conversation-title "向量库测试_100题_YYYYMMDD_HHMMSS" `
  --json-output ".\高炉前端数据\智能助手\tests\bf_dialog_eval_page_conversation_100_results.json" `
  --md-output ".\高炉前端数据\智能助手\docs\高炉向量库页面专用对话评测报告_100条.md"
```

这种方式会把 100 个问题连续写入同一个 8092 对话，适合页面观察，但由于会带上近期会话历史，后半段问题会更慢，也可能受到前文上下文影响。若只评估单题独立能力，仍优先使用非连续会话评测。

## 8. 后续优化比较规则

每次优化向量库、意图识别、query rewrite、术语扩展、rerank 或系统提示词后，应重复运行同一套 100 条对话框评测，并比较：

- 平均评分是否提升。
- 低于 60 分的问题是否减少。
- 工况诊断和参数优化是否提升且不牺牲工艺问答。
- 报告类是否仍然不补充未提供数据。
- 模糊问法是否能被转换成规范工艺术语。
- 类案例问题是否明确说明案例库边界。
- 平均耗时和最大耗时是否仍可接受。
