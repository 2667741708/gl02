## 原生 PostgreSQL 16 管理员连接

仅限本机授权运维使用，不得写入前端代码、日志、截图、公开文档或接口响应。

```text
host=127.0.0.1
port=18000
database=postgres
user=postgres
password=postgres
service=postgresql-x64-16
```

PowerShell 临时验证示例：

```powershell
$env:PGPASSWORD = 'postgres'
& 'C:\Program Files\PostgreSQL\16\bin\psql.exe' -w -h 127.0.0.1 -p 18000 -U postgres -d postgres -c 'SELECT current_user, version();'
Remove-Item Env:PGPASSWORD
```

项目后续默认使用本机原生 PostgreSQL；Docker PostgreSQL 仅作为历史迁移来源，不作为新的运行目标。

## 一期 MES 正式库 Vastbase

更新时间：2026-07-16

授权截图补充了以下连接元数据：

```text
Navicat connection name=一期MES正式库
host=10.10.181.195
port=5432
database=vastbase
administrative user=vbadmin
read-only login role=lg_fq（首字符为小写字母 l）
password=本机完整凭据保存在 PT/imes_vastbase.local.env；该文件必须被 .gitignore 排除
```

`vbadmin` 按高权限管理账号处理，只能用于用户明确授权的数据库维护，不得配置到前端、MCP、导出程序或自动值守。业务账号为 `lg_fq`，截图字体中的小写字母 `l` 容易误读为数字 `1`；角色存在性和 `CONNECT`、schema `USAGE`、视图 `SELECT` 权限必须通过实际只读登录核查。项目不会根据截图自动执行 `CREATE ROLE` 或 `GRANT`。

现有程序统一沿用 `IMES_DB_HOST`、`IMES_DB_PORT`、`IMES_DB_NAME`、`IMES_DB_USER`、`IMES_DB_PASSWORD`。用户已明确授权将完整凭据保存在 `PT/imes_vastbase.local.env`；文件由根目录 `.gitignore` 排除，通过 [本机加载器](../PT/load_imes_vastbase_local.ps1) 注入当前 PowerShell。服务端固定目标为 `10.10.181.195:5432/vastbase`，但本机默认不直连：必须先启动 [220.12 回环转发](22012_IMES跳板转发与MCP.md)，再使用加载器的 `-Relay` 切换为 `127.0.0.1:15433`，并由只读脚本或 MCP `relay` 模式查询。不带 `-Relay` 的直连仅用于用户明确要求的专项对照。Navicat 和 PowerShell 操作步骤见 [PT 交接说明](../PT/imes.md#一期-mes-正式库-vastbase-连接方式2026-07-16)。

2026-07-16 15:08 已用 `lg_fq` 实际直连验证：认证成功、会话只读，且对 `public.v_qpes_steel_final`、`public.v_qpes_mat_final`、`public.v_qpes_inner_batch_insp_final_sample`、`public.v_qpes_sinter_machine_sample_insp_final`、`public.v_qpes_slag_insoection_final` 均有 `SELECT` 权限。视图数据范围和逐字段字典见 [MES 数据集说明第9节](mes数据集.md#9-lg_fq-五个授权视图与逐变量字典2026-07-16)。
