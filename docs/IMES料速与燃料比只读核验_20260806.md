# IMES 料速与燃料比只读核验（2026-08-06）

## 结论

- Vastbase 只读元数据、`public.t_ipes_out_put`、`public.t_ipes_cond`，以及 220.12 的 `bf_imes.raw_rows` 镜像中，均没有发现名为“料速”“燃料比”“综合燃料比”“焦比”“煤比”或对应英文别名的直接字段。
- IMES 已具备计算料速的基础数据：批次投料接口提供 `charge`、`lot/workdate/workdate2`、`remark3`、`mining_batch_sum`、`coke_charge_sum` 和 `value_sum`。因此可派生“批/小时”或“分钟/批”，但二者不是同一指标，必须先由现场统一口径。
- IMES 已具备焦炭与铁量基础数据：焦批明细提供 `coke_charge_sum`，生产实绩提供 `ironquan`。但完整燃料比通常还需要喷煤量；本项目的喷煤率/整点累计来自 pSpace，不是 IMES 直接字段。因此“综合燃料比”应被建模为跨源派生指标，而不能标记为 IMES 原始值。
- 2026-08-08 已补充 Raqsoft 作业日志报表读取链路：报表 M 列本身是页面公式列，原始 HTML 常为空，程序按页面公式重算并写入 `report_fuel_ratio`；D 列明确是“批数”，不是已确认的料速，因此 `material_rate` 继续标记 `semantic_unconfirmed`。
- 燃料比现在已具备“报表原值/全部单元格 + 公式重算值 + 质量语义”的落库闭环；料速仍未完成现场语义确认，不能把批数直接当成料速。

## 建议的待确认语义

| 指标 | 建议公式 | 必须确认的边界 |
| --- | --- | --- |
| 料速 | `有效料批数 / 有效小时数`（批/小时），同时保留相邻批次平均间隔（分钟/批） | 用矿批、焦批还是完整装料周期；异常/重复批次如何排除；班、日还是滚动窗口 |
| 焦比 | `干焦量 / 铁水量 × 1000`（kg/tHM） | 干/湿基、焦丁是否计入、铁量过账时间和炉次归属 |
| 煤比 | `喷煤累计量 / 铁水量 × 1000`（kg/tHM） | pSpace 积分质量、班/日/炉次时间边界、缺测覆盖率 |
| 综合燃料比 | `(干焦量 + 喷煤量 + 现场确认的其他燃料量) / 铁水量 × 1000`（kg/tHM） | 现场燃料构成、计量修正、跨源时间对齐和迟到数据重算 |

在上述口径确认前，程序只保留只读审计和原始数据同步，不新增正式派生字段。
