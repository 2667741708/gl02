# 8093 智能助手自动诊断—修复—验收工具

追踪编号：`OPS-8093-ASSISTANT-AUTO-RECOVERY-20260805`  
生效日期：2026-08-05  
统一入口：`tools/assistant_8093_auto_recovery.py`

## 1. 目标与结论

本工具把以往分散的服务检查、端口探测、进程环境、守卫日志、知识检索、模型驻留、异常日志、修复部署和真实问答验收合并为一个可分类、可拒绝、可追踪的入口。正常网络下，`diagnose` 应在 1–2 分钟内给出分类；`recover` 的服务恢复与验收预算为 10–15 分钟，文档生成在服务阶段结束后单独运行。

当前生产口径已经固定：8093/8094 使用 `BF_QA_KNOWLEDGE_SEARCH_MODE=keyword`，共享 11434 使用 `OLLAMA_MAX_LOADED_MODELS=1`，只驻留 `chiqiong-blast-furnace:latest`。发现空值或 `hybrid` 漂移时，分类器直接调用已有 keyword 受控部署器，不再重复调查已经确认的 embedding/单槽竞争风险。

## 2. 固定流水线

1. 本机并行检查私网/VPN 路径、SSH 22、PostgreSQL 5432、8093、11434。
2. 如果必需远端端口不全，启动 aTrust 并等待恢复；失败则退出，不建立 SSH/SFTP。
3. 从远端受控包运行一个合并只读探针，一次收集服务、监听 PID、实际进程环境、守卫状态/日志、默认知识搜索、Ollama 驻留模型和最近问答异常。
4. 自动分类为健康、已知 keyword 漂移、已知守卫合同漂移、多个已知漂移，或需要人工审计的未知状态。
5. 只有命中已知哈希且确需修复时，才由对应部署器备份并执行最小变更；未知哈希拒绝覆盖。
6. 重新检查实际监听进程环境、服务/端口、默认知识搜索和模型驻留，不用配置文件代替运行态证明。
7. 只发送一次真实 SSE 问答；失败不自动重试，避免重复请求堆积。
8. 先保存 JSON 并结束服务阶段；随后由独立 `docs` 命令生成 Markdown、DOCX 和追踪记录。

备份是条件阶段：健康状态不会制造无意义备份或重启；只有真正部署时才建立带时间戳的远端备份。

## 3. 远端包与 PowerShell 可靠性

远端包目录固定为：

```text
C:\ProgramData\BFV4\assistant-auto-recovery\packages\<package_id>
```

包 ID 来自 manifest 内容哈希。预置时先原子写入 payload，最后写 manifest；随后逐文件重新计算 SHA-256。每个 PowerShell 文件在传输字节层增加 UTF-8 BOM，保证 Windows PowerShell 5.1 正确解析中文项目路径。

远端执行只使用一个短命令形态：

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<package script>"
```

禁止把多阶段逻辑塞入 `-Command`、`-EncodedCommand`、内联 ScriptBlock 或 SSH 嵌套引号。这样避免每次上传、ANSI 编码、命令长度和多层解析器错误。

## 4. 自动分类与写入边界

| 分类 | 条件摘要 | 动作 |
|---|---|---|
| `healthy` | 服务/端口/状态正常；现行配置与守卫哈希；进程和默认搜索均为 keyword；只驻留批准模型 | 不部署、不重启；继续唯一一次 SSE 验收 |
| `keyword_mode` | 已知历史配置哈希，或进程/默认检索为空或 hybrid | 备份，仅运行 keyword 部署器，仅重启 8093 |
| `guard_contract` | 已知旧守卫/配置哈希或 3/1/15/600 合同漂移 | 备份，仅运行守卫受控部署器 |
| 多个已知漂移 | 两类已知条件同时成立 | 固定先守卫、后 keyword，再做一次总复核 |
| 人工阻断 | 未知配置/脚本哈希、非批准模型、服务或接口异常不能归入已知修复 | 拒绝自动覆盖，报告证据和阻断项 |

## 5. 输出内容

JSON 报告至少包含：

- VPN/私网、SSH、PostgreSQL、8093、11434 连通性与耗时；
- `BFV4PreviewProxy8093`、`BFOllama11434`、`BFV4PreviewWs8768`、PostgreSQL 服务状态；
- 5432、8093、8094、8768、8770、11434 监听 PID；
- 8093 实际 `BF_QA_KNOWLEDGE_SEARCH_MODE` 和 11434 实际单模型/驻留参数；
- 守卫任务、状态文件、阈值、冷却、最近健康日志与重启记录；
- 不传 `mode` 的默认知识检索模式、候选数和证据；
- `/api/ps` 当前驻留模型；
- 最近 `/api/qa/chat` 请求、异常匹配与 runner 记录；
- 修复前/后分类、部署动作、唯一 SSE 事件/耗时和受保护状态。

日志中的历史 `Traceback` 只作为证据，不在当前服务、检索、模型、守卫全部健康时单独把状态判成故障；需要结合时间和请求进行人工审阅。

## 6. PowerShell 5.1 数字键回归

本轮把监听端口从 JSON 的数字字符串键转换为显式数组：

```json
[{"port": 8093, "listening": true, "pid": 6892}]
```

测试不是用 Python 模拟 PowerShell，而是调用本机真实 `powershell.exe -File`。测试先给实际 `.ps1` 生成与远端一致的 UTF-8 BOM 副本，再让 PowerShell 5.1 读取包含 `"8093"`、`"8768"`、`"11434"` 键的 fixture，验证输出稳定为数组。这会在部署前发现 `PSCustomObject` 数字属性/JSON 序列化回归。
