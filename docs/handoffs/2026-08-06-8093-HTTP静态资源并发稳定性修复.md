# 8093 HTTP 静态资源并发稳定性修复交接

追踪编号：`ERR-8093-STATIC-ASSET-EMPTY-RESPONSE-20260806-R1`。

## 结论

`http://10.30.220.12:8093/#overview` 与带 `?ws_port=8768&release=...` 的地址由同一个 `INDEX_FILE` 返回。URL fragment `#overview` 不会发送到服务器；8093 页面默认 `ws_port=8768`；`release` 参数不参与页面业务逻辑。修复前两地址的 HTML 字节数和 SHA-256 已证明一致。

用户看到页面不同的直接原因是同一 HTML 的静态模块加载不完整。生产 `ThreadingHTTPServer` 使用默认监听积压队列 5，浏览器冷启动并发请求 CSS、JS、Three.js、GLB 和 API 时会溢出；220.12 本机复现 20 请求仅 12 成功，失败为 `WinError 10061`。页面还用 `Date.now()` 强制跳过 8.2 MB GLB 缓存，服务又对全部静态资源发送 `no-store`，放大了故障概率。

## 实现

- [8093 后端](../../高炉前端数据/智能助手/backend/ollama_proxy_server.py)：新增 `BlastFurnaceThreadingHTTPServer`，默认队列 128（环境变量 `BF_8093_HTTP_REQUEST_QUEUE_SIZE`），启用 daemon threads；版本化资源返回 immutable 缓存头和 ETag/304；服务 HTML 时把随机 GLB URL 重写为固定发布版本，不改活动页面清单。
- [本机页面](../../高炉前端数据/frontend_dashboard_v3.server.html)：两个 GLB 加载点固定为 `v=20260806-static-stability-r1`，本机继续作为最新源码。
- [并发探针](../../tools/probe_8093_http_stability.py)：浏览器式 10 资源并发读探针。
- [生产部署器](../../tools/remote_guarded_deploy_8093_http_static_stability.ps1)：不使用全局部署互斥锁；只停止/启动 8093；保护 8768、8094、8770；失败回滚；强制检查 30 请求、缓存头和 ETag。
- [合同测试](../../tests/test_8093_http_static_stability.py)与[部署器测试](../../tests/test_8093_http_static_stability_deployer.py)：8 项通过。
