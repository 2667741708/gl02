# MCP 多轮规划与顶温/顶压点位名称审计

> 状态：2026-08-13 追加 pSpace 权威目录复核并完成本机兼容修复；未部署生产  
> 问题编号：`Q-8093-MCP-POINT-NAME-PLANNING-20260813`  
> 最后核对：2026-08-13  
> 适用边界：220.12 当前 Ollama 模型、GL02 MCP 目录与本机 8093/8094 问答编排代码

## 结论

当前模型和编排器具备多轮工具规划能力。受控两轮实测中，模型第一轮调用
`find_gl02_variables(keyword="A点顶压")`，收到模拟的权威目录结果
`P_top_A` 后，第二轮正确调用
`query_gl02_sensors(query_type="latest", variables=["P_top_A"])`。
该探针没有执行数据查询。

但自然语言点位名称尚未统一，不能把“具备多轮规划”理解为“所有口语问法都能稳定命中”。
当前至少有三份会影响解析的来源：正式物理点位清单、MCP 映射/别名、问答后端的
`SPOKEN_MCP_VARIABLE_ALIASES`。它们已出现可观测漂移：

- 修复前，单轮模型直接规划“顶温 A-D、顶压 A-D”时，温度使用了正确的
  `T_top_A-D`，压力生成了当时目录未接受的 `P_top_A-D`；目录当时暴露的是历史应用名
  `P_top_gas_A-D`。追加权威复核后，该组已统一为对外标准名 `P_top_A-D`，旧名仅保留为
  兼容别名。
- 修复前，本机确定性口语解析会把部分 A-D 问法折叠为聚合变量 `T_top`、`P_top`；现已
  对“顶温A-D + 顶压A-D”“四个顶温和四个顶压”“上升管煤气温度和压力”展开八点。
- 修复前，220.12 目录对“A点顶温/A点顶压”的模糊解析会误落聚合变量；本机修复已补齐
  双向语序的精确别名。220.12 生产目录仍待受控部署后切换。
- 使用标准 ID 直接调用 220.12 的 `query_gl02_sensors` 时，八个点位全部查询成功且
  均返回值，证明采集、映射和 MCP 数据执行层具备能力。

因此，当前准确表述是：**数据层支持八点查询，模型支持目录驱动的多轮规划，本机已修复常用
口语到标准 ID 的链路；220.12 生产尚未部署本轮名称修正。**

| 口语名称 | 标准变量 ID | 物理点位 ID |
|---|---|---|

## 建议的可维护升级

建立单一的语义点位目录，并从物理点位清单和人工审定别名生成运行时产物。建议每条至少包含：

- `canonical_variable_id`、`display_name`、`point_id`、`unit`；
- `family_id`、`member`、`aggregate_of`；
- 规范化 `exact_aliases`，同时覆盖“顶温A”和“A点顶温”等语序；
- 数据来源、状态、版本和更新时间。

解析顺序固定为：精确别名 → 家族/成员规则展开 → 目录搜索 → 模型规划。只要用户明确给出成员
A-D，解析器就必须禁止返回聚合变量。模型生成的标准 ID 还必须经过目录校验；目录未知的
标识应被拒绝并强制回到 `find_gl02_variables`，不能直接发往数据工具。

问答后端和 MCP 服务应读取同一份编译目录，逐步取消两边独立维护的手写别名。物理点位清单
继续作为采集 ID 权威来源，语义目录作为名称、家族和口语映射的权威来源，两者职责不能混用。

## 2026-08-13 pSpace 权威复核与修正

通过 220.12 的官方 Python SDK 只读连接 `10.22.181.243:8889`，直接对
`\冀南钢铁\SIO\GL02\LD` 执行 `QueryTag` 和 `GetTagProps`。该父节点共有 203 个直接
子点；目标八点均存在。pSpace 返回的压力点权威属性是：

| pSpace 属性名 | pSpace 长名 | pSpace 描述 |
|---|---|---|
| `SIO_GL02_LD_T0067` | `\冀南钢铁\SIO\GL02\LD\SIO_GL02_LD_T0067` | `2号炉炉顶_上升管煤气压力A` |
| `SIO_GL02_LD_T0068` | `\冀南钢铁\SIO\GL02\LD\SIO_GL02_LD_T0068` | `2号炉炉顶_上升管煤气压力B` |
| `SIO_GL02_LD_T0069` | `\冀南钢铁\SIO\GL02\LD\SIO_GL02_LD_T0069` | `2号炉炉顶_上升管煤气压力C` |
| `SIO_GL02_LD_T0070` | `\冀南钢铁\SIO\GL02\LD\SIO_GL02_LD_T0070` | `2号炉炉顶_上升管煤气压力D` |

结论需要分层表达：pSpace 的物理点名不是 `P_top_A`，也不是 `P_top_gas_A`；它是
`SIO_GL02_LD_T0067`。`P_top_*` 是本项目的业务变量层。按用户确认的稳定业务口径，本机
MCP 目录、口语解析和点位清单已改用 `P_top_A-D`，同时把 `P_top_gas_A-D` 作为兼容别名
映射到同一四个 pSpace 物理点。历史模型特征暂不强制重命名，通过边界适配继续读取同一数据，
避免破坏已训练模型和既有历史序列。

本机验证：MCP/问答聚焦回归 `40 passed`；八点口语探针已稳定生成
`T_top_A-D + P_top_A-D` 及单次 `query_gl02_sensors` 计划。生产尚未切换，需另走 8093
受控部署和现场验收。
