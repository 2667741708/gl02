## 结论

8093 的实时 MCP 层能够读取 GL02 传感器、返回时间窗统计，并能在一个跨源 DAG 中并行调用
IMES 与 GL02 相关性计算工具。三次明确编号的 SSE 请求均完成，工具层通过 `3/3`。

最终答案层通过 `0/3`：底层数据没有丢失，但 T1/T2 的确定性格式化器只输出少数字段，
没有让模型完成用户要求的证据推断和 CV 计算；T3 的相关性 `derived` 字段没有进入跨源事实快照，
模型因此错误声称没有 r 和对齐样本数。

## 根因定位

1. `deterministic_mcp_answer()` 针对 `query_gl02_sensors` 只渲染均值、最低、最高和趋势；
   它返回非空文本后，问答循环立即结束，不再让模型完成题目中的推断、公式或字段要求。
2. 跨源执行器保留了 `plot_gl02_analysis` 的完整 JSON，但事实抽取只形成 chart URL；
   `pearson_r` 和 `aligned_count` 留在 `source_status.result_text`，没有成为模型分析上下文中的事实。
3. 因而这不是数据库或 MCP 计算失败，而是“完整工具结果 → 最终答案”之间的证据投影合同不完整。

## 最小修复建议

1. 给确定性格式化器增加用户请求字段投影，或在题目含“标准差/CV/公式/推测/证据是否足够”时，
   将完整工具消息交给一次 `tools=None` 的受控最终模型回合；不能让模型重新查库。
2. 把 `plot_gl02_analysis.derived.correlation` 映射为正式跨源事实：`pearson_r`、
   `aligned_count`、`linear_slope`，并保留变量、时间窗、来源。
3. 最终回答前执行证据完整性检查：凡用户明确要求的字段在工具结果存在但答案缺失，应判失败，
   不写成成功验收。
