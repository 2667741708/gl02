## 3. 根因分层

1. **测试输入层**：39 条后续轮和 3 条模板占位符缺少前置条件，不能用于单轮准确率。采集器必须在发送前验证依赖。
2. **意图和来源层**：目录、口语观察、炉次、烧结、诊断历史、报表正文及公共规则来源会被局部关键词抢走。
3. **对象和上下文层**：别名、对象族、无归属指代、会话 owner、窗口和基线没有统一绑定。
4. **执行层**：工具发现预算代替了确定性目录调用；成功结果可能在后续失败时丢失；复合步骤缺完成条件。
5. **证据和渲染层**：单位、时间、质量、对象值关系、图表和来源未形成统一 answer item；单纯数字白名单不能阻止“数值绑错对象”。
6. **解释层**：模型会遗漏因果边界、阈值依赖或子任务，也会被硬 token 上限截断。事实段和解释段必须分开验收。
7. **知识治理层**：来源覆盖、范围正确和语义正确是三道不同门；冲突 oracle 不能用多数答案自动覆盖。
