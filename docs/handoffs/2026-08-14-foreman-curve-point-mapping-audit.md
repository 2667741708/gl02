## 结论

- 截图中的 `P_top=22.381063 kPa` 不是前端归一化坐标被误显示。220.12
  `bf_sensor.one_minute_values` 在 `2026-08-14 06:27:00` 保存的原始值就是
  `22.381063`；绕过 PostgreSQL、按单点直接读取 pSpace 原始历史，结果仍为
  `22.381063`。`P_top -> SIO_GL02_LD_T0034 -> 2号炉炉顶_顶压平均` 映射正确。
- 截图上方卡片是 `12:29` 左右的 pSpace 当前值，下方曲线选择的是 `06:00–08:00`
  历史范围。两者相隔约六小时，页面目前不会让顶部卡片随历史光标或历史区间联动，因而
  不能直接用顶部 `257.9 kPa` 对比 06:27 的曲线提示值。
- 主图为多量纲“泳道归一化”显示，纵轴 `0–100` 只表示曲线分层位置，不是各传感器物理
  数值；右键提示的第三维才是原始历史值。页面缺少醒目的口径说明，容易被理解为曲线与点位
  串接。
- `L_south/L_north -> SIO_GL02_LD_T0075/T0076` 映射正确。两点在 `2026-08-14 14:04:45`
  的 pSpace 实时值为 `-0.43427/-0.46800 m`，与现场工长页的约 `-0.45 m` 同口径；两小时
  原始历史分别覆盖 `-0.48–1.73 m`、`-0.48–2.82 m`，呈现正值工作下降段与约零位负值
  提尺区的周期波形。pSpace 的“下限位24米/下极限位6米”是误导性注释，不代表布尔限位。
- `Hopper_weight_set` 没有检出可直接登记的单一 pSpace 点。旧业务路径 `GD_1\罐重设定`
  的四种可能长名均返回“测点不存在”。可复现的实际口径是把炉顶 1–11 号布料重量设定
  `SIO_GL02_LD_T0115/T0116/T0117/T0119–T0126` 按时刻状态求和；当前合计 `49.14 t`，
  最近半小时原始变更批次出现约 `48.77–50.71 t`、约 `11.09–11.28 t` 与 `0 t` 三种阶段，
  与罐重设定的阶梯曲线特征一致。该量必须登记为派生变量，不能伪装成单一物理点。
- `GasUtil` 历史原值使用 `0–1` 比例，而曲线单位标为 `%`；当前卡片与历史提示应统一
  `×100` 后保留两位小数。

## 根因分层

1. `P_top` 截图差异的根因是“顶部实时卡片”和“手动历史时间窗”没有时间联动，不是点位串接。
2. 主图采用泳道归一化坐标，但页面没有解释纵轴语义，进一步放大了误解。
3. `GasUtil` 是真实的单位换算遗漏：当前卡片按百分比展示，历史提示仍保留 0–1 原值。
4. 下图的正式清单缺口只剩罐重设定；南北尺的点位本身正确，问题是 pSpace 元数据描述与
   实际连续量语义不一致。

1. 在历史区间激活时明确显示“顶部为当前值，曲线为所选历史”，并支持历史光标联动的快照值。

3. 统一 `GasUtil` 当前值和历史值为百分比口径，再传给曲线与右键提示。
4. 给 1–11 号布料重量设定登记独立物理变量，按一分钟状态前向保持后求和，写入派生变量
   `Hopper_weight_set`；派生值缺少任一启用分量时必须标记不完整，不能把缺项当零。

   点位 ID 不变，不切换到 EQ 子树的 1#/2#探尺候选。
