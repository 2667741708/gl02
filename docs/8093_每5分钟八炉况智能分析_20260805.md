# 8093 每5分钟八炉况智能分析

需求编号：`REQ-8093-DIAGNOSIS-AI-FIVE-MINUTE-ANALYSIS-20260805`

增强需求：`REQ-8093-DIAGNOSIS-AI-EVIDENCE-GUIDANCE-20260805`

## v2 数据化解释与指导

每类智能分析现在会从服务端读取计算规则分所需的真实派生特征、最近60分钟变量和30天基线，向高炉长说明“哪些项目变高/变低、最近5分钟变化多少、相对基线处在什么位置、对应规则权重和门槛是什么”。这些数值来自服务器，不允许模型或浏览器自行填写。

同一批次还只读复用调剂引擎1和知识库：调剂引擎1提供动作状态、触发证据、前置/阻断条件、建议幅度、观察窗口、审批要求和《三规二制》章节；知识库提供可追溯资料片段。弹窗把这些内容组合成较详细的口语化回答、数据依据和指导意见。

为防止大模型编造现场数据，Prompt只允许引用服务端分配的 `driver_id/action_id/chunk_id`。任何未知ID都会使该批结果校验失败；最终展示的变量卡、建议卡和知识卡由服务端可信上下文附加，不从模型自由文本提取。该功能只解释既有分数并给出只读建议，不重新计算规则分，也不连接生产控制。

## 功能口径

8093后台按生产诊断时间划分5分钟时间桶。每出现一个新的诊断时间桶，只调用一次受控高炉大模型，同时生成正常顺行、低料线、边缘煤气流发展、边缘不足/中心过吹、管道行程、热制度下行、热制度上行、崩滑料/悬料八类分析，并保存到220.12回环PostgreSQL。

诊断页八张炉况卡继续保留人工评分入口。点击任一炉况卡时打开同一个“智能分析与人工评分”窗口，先显示该炉况在当前5分钟点的模型判断，再显示原有的人工匹配分和建议表单。关闭窗口不会写人工评分；智能分析是后台派生结果，与人工评分事件相互独立。

模型输出包括：

- 当前炉况的系统规则符合度；
- 模型证据吻合度，明确不是概率；
- 证据支持、存在可能、当前不支持或数据不足；
- 简明分析、支持证据、矛盾证据、下一5分钟关注项和数据限制；
- 风险变化方向：上升、平稳、下降或暂不确定。

模型没有权限修改八类规则分、主诊断、人工评分、安全门禁或生产控制。浏览器只提交所点击的炉况标签；诊断快照、八类分数、证据、覆盖率和最近历史由服务端从 `bf_sensor.diagnosis_snapshots` 重新读取。

## 数据流

```text
bf_sensor.diagnosis_snapshots 最新快照＋最近12点历史
  + bf_sensor.one_minute_values 最近60分钟
  + bf_sensor.daily_baselines 30天基线
  + 调剂引擎1只读结果 + 知识库检索证据
  -> 服务端5分钟时间桶、规则驱动ID与可信白名单上下文
  -> 一次模型请求生成八类JSON分析
  -> bf_assistant.diagnosis_ai_analysis_snapshots
  -> GET /api/diagnosis-ai-analysis?label=<炉况键>
  -> 诊断卡“智能分析与人工评分”窗口
```

后台每30秒检查一次是否出现新时间桶，不代表每30秒调用模型。相同 `furnace_id + bucket_ts + prompt_version` 只有一行派生状态；完成结果直接复用。失败后默认至少等待120秒才允许重试，避免页面刷新或多人点击重复占用共享模型。

## API

### `GET /api/diagnosis-ai-analysis?label=<key>`

免登录读取当前5分钟桶中所选炉况的分析。`label` 只能是八类内部键之一。未生成时返回HTTP 202和 `preparing/reasoning`；完成或处于可展示失败状态时返回HTTP 200。接口不会接受浏览器上传的诊断分数。

### `POST /api/diagnosis-ai-analysis/retry`

请求体只允许包含所选 `label`。只重试当前服务端快照；已完成结果不会重复生成，失败后的冷却期内返回429。

## 数据表

`bf_assistant.diagnosis_ai_analysis_snapshots` 是可重新生成的派生状态表，不是人工审计事件表。主要字段：诊断快照ID、诊断时间、5分钟桶时间、主诊断、八类规则分、白名单上下文、八类分析JSON、生成状态、尝试次数、错误类型、Prompt版本、快照哈希和完成时间。唯一约束为：

```text
(furnace_id, bucket_ts, prompt_version)
```

人工评分仍分别保存在 `diagnosis_review_events` 和 `diagnosis_manual_score_events`，不会被模型分析覆盖。
