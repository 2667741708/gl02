## 交付边界

- 原型只绑定本机回环地址，页面/API 为 `8096`，实时桥接为 `8769`。
- 220.12 仅作为实时诊断只读来源；本次没有修改、停止或部署 220.12 的 8093、8094、8768和数据库服务。8096复用同一主HTML和诊断数据合同，但部署与运行均与8093/8094隔离。
- 人工复核只允许写入由 `BF_DIAG_REVIEW_PG*` 显式指定的回环 PostgreSQL。目标不是 `127.0.0.1`、`localhost` 或 `::1` 时服务拒绝写入，且不会回退到 `GL02_PG*`。
- 现有 `frontend_dashboard_v3.server.html` 不硬编码原型资源；只有 `BF_DIAGNOSIS_REVIEW_ENABLED=1` 时，本机代理才注入独立 JS/CSS。
- 专用启动器设置 `BF_SKIP_ASSISTANT_STARTUP=1`，避免这个隔离原型启动时初始化无关的问答/RAG写表；不影响普通8092启动口径。

## 数据与交互

诊断源复用 `bf_sensor.diagnosis_snapshots` 已有主诊断、主分、次诊断、证据、数据覆盖率和八类 `raw_scores`。服务端以诊断时间去重并取最新快照。连续异常段按“同一异常标签且相邻快照不超过10分钟”向前归并；标签变化、恢复正常或间隔超过10分钟会形成新异常段。

主诊断不是“正常顺行”时自动显示居中模态框。把握分明确解释为“规则符合度，不是统计概率”，同时显示其余七类候选分数。`cold/hot` 只在界面映射为“热制度下行/热制度上行”，不改变数据库键。关闭后保留“异常待复核”按钮；异常段自动弹出记录保存在浏览器本地存储，同一异常段刷新页面也不会重复自动弹出。

复核结论为：`correct`（诊断正确）、`incorrect`（诊断不正确）和 `uncertain`（暂无法判断）。`incorrect` 必须选择实际主炉况，可以选择实际次炉况。异常弹窗另外提供可选的0～100人工匹配分和可选建议；关闭弹窗不会伪造事件。

炉况诊断页八张炉况卡均可点击打开独立“高炉长人工评分”窗口，不依赖异常自动弹窗。人工匹配分与建议至少填写一项才能保存；二者都不填时可以直接关闭。每条记录绑定服务端重新读取的诊断快照ID和时间戳，系统八类分数保持不变，人工分作为独立字段追加保存。未提交人工分时，炉况数据仪表盘仍展示系统分，并显示“未打分”。

## 会话、API与表

登录账号、密码、角色和会话密钥来自环境变量。登录成功签发 HMAC 签名、`HttpOnly`、`SameSite=Strict` Cookie；允许角色默认只有“高组长”。接口保持原登录响应兼容，并新增：

- `POST /api/auth/logout`
- `GET /api/diagnosis-review-context`
- `GET /api/diagnosis-reviews`
- `POST /api/diagnosis-reviews`
- `GET /api/diagnosis-manual-scores`
- `POST /api/diagnosis-manual-scores`

提交接口只接收人工判断、目标炉况、可选人工分/建议、快照标识和幂等键。八类分数、证据、覆盖率和诊断时间由服务端重新读取只读来源；浏览器不能覆盖。异常复核追加写入 `bf_assistant.diagnosis_review_events`，手动评分/建议追加写入 `bf_assistant.diagnosis_manual_score_events`；两表的 `idempotency_key` 均唯一。测试数据的 `snapshot_source` 固定为 `local_fixture`。表结构见 [postgresql_diagnosis_review.sql](../高炉前端数据/智能助手/backend/schema/postgresql_diagnosis_review.sql)。

炉况数据仪表盘新增“高炉长评分”页签和 `/api/diagnosis-foreman-scores` 只读查询/CSV/XLSX导出。默认显示真实只读诊断；“本机测试记录”必须显式选择，避免与真实记录混合。每个诊断时间点展开八类系统分，并并列显示人工分、建议、评分人、角色、提交时间和来源模式。

## 配置与启动

必需环境变量：

- `BF_DIAG_REVIEW_PGPASSWORD`：本机原生 PostgreSQL 复核写账号密码。
- `BF_LOGIN_ZHGL_PASSWORD`：本地测试高组长账号密码。
- 实时模式还需要 `GL02_PGPASSWORD`，只用于读取220.12诊断源。

可选变量包括 `BF_DIAG_REVIEW_PGHOST`（默认 `127.0.0.1`）、`BF_DIAG_REVIEW_PGPORT`（默认 `18000`）、`BF_DIAG_REVIEW_PGDATABASE`（默认 `bf_trend`）、`BF_DIAG_REVIEW_PGUSER`（默认 `postgres`）、`BF_AUTH_SESSION_SECRET`、`BF_DIAG_REVIEW_ALLOWED_ROLES`。

```powershell
python tools/start_diagnosis_review_preview.py --fixture-only
python tools/start_diagnosis_review_preview.py
```

启动器会在存在时把仓库受控依赖目录 `.tmp_pylibs` 加入子进程搜索路径，以复用项目现有的 `psycopg`；不会在日志中打印密码。

`--fixture-only` 只启动本机 `8096` 页面/API和固定测试场景，不启动 `8769`，也不读取220.12。如果启动器报告“本机端口 8096 已被占用”，它会安全退出，不会覆盖或自动结束既有进程。先执行以下命令取得监听 PID：

```powershell
netstat -ano | Select-String -Pattern ':8096\s+.*LISTENING'
Get-Process -Id <PID> | Select-Object Id, ProcessName, Path, StartTime
```

只有在通过进程信息或 `http://127.0.0.1:8096/api/diagnosis-review-context` 确认它是旧的本机诊断复核原型后，才可执行 `Stop-Process -Id <PID> -Force`；若 Windows 返回 `Access is denied`，应在管理员 PowerShell 中对同一精确 PID 执行 `taskkill /PID <PID> /F`。禁止使用 `taskkill /IM python.exe` 批量结束 Python 服务。释放后再次执行启动命令即可；启动成功后终端持续显示服务日志是正常现象，按 `Ctrl+C` 停止。

测试场景页：`http://127.0.0.1:8096/diagnosis_review_local_test.html`。它仅允许回环地址，并提供正常顺行、热制度下行、热制度上行、低料线、管道行程五种状态。
