## 运行原则

- 使用 PowerShell 7 Core 和无 BOM UTF-8；不新增 Windows PowerShell 5.1 入口。
- 本机日常数据库目标是原生 PostgreSQL。端口和版本先探测，不从旧脚本默认值推断。
- 生产服务、220.12 数据库和 IMES/Vastbase 默认只读；本机启动不等于获得远端写权限。
- 先 dry-run 和检查端口，再启动；已有用户进程不按进程名批量结束。

## 前置检查

在项目根目录执行：

```powershell
pwsh.exe -NoLogo -NoProfile -File .\tools\verify_pwsh7_utf8.ps1
```

确认 PostgreSQL 服务、监听端口和服务端版本。账号从
[数据库账号配置说明](数据库账号配置说明.md) 或受控环境变量读取，不在命令历史中写密码。
Python 依赖以仓库 requirements 文件和具体模块 README 为准；缺失依赖可按项目规则安装，
但应记录新增包、用途和验证命令。

## 总入口

[start_v3_full.ps1](../start_v3_full.ps1) 负责助手、前端、诊断、实时桥接和本地同步循环。
默认主连接与同步目标统一为本机原生 PostgreSQL：
`127.0.0.1:18000/bf_trend`。账号默认 `postgres`，密码只从
`GL02_LOCAL_PGPASSWORD` 读取，不写入脚本或普通日志。

首次运行或新终端中先注入本机凭据：

```powershell
$env:GL02_LOCAL_PGUSER = 'postgres'
$env:GL02_LOCAL_PGPASSWORD = '<从受控配置输入，不写入脚本>'
```

可选变量与默认值：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `GL02_LOCAL_PGHOST` | `127.0.0.1` | 本机原生 PostgreSQL，仅应使用回环地址 |
| `GL02_LOCAL_PGPORT` | `18000` | 当前原生 PostgreSQL 16 受控端口 |
| `GL02_LOCAL_PGDATABASE` | `bf_trend` | 本机业务库 |
| `GL02_LOCAL_PGUSER` | `postgres` | 默认本机账号，可由获批本机角色覆盖 |
| `GL02_LOCAL_PGPASSWORD` | 无 | 必填敏感项，只从进程环境读取 |
| `BF_USE_EXISTING_PG_ENV` | 未启用 | 显式设为 `1/true/yes` 时才保留既有 `GL02_PG*` 主连接 |

先检查计划动作：

```powershell
pwsh.exe -NoLogo -NoProfile -File .\start_v3_full.ps1 -DryRun
```

确认端口、数据库环境和将启动的进程后，再运行：

```powershell
pwsh.exe -NoLogo -NoProfile -File .\start_v3_full.ps1
```

常用开关可通过脚本参数查看，当前包括 `-Restart`、`-SkipAssistant`、`-SkipFrontend`、
`-SkipDiagnosis`、`-SkipRealtimeBridge`、`-SkipLocalSyncLoop` 及端口覆盖参数。

## PostgreSQL 选择规则

默认模式为 `local-native`：启动器用 `GL02_LOCAL_PG*` 覆盖当前进程中可能指向 220.12 的
`GL02_PG*`，助手、诊断和实时桥接因而统一读取本机原生实例；本地同步子进程继承同一套
`GL02_LOCAL_PG*`。脚本已删除 Docker `15432` 和本地硬编码密码回退。

只有操作者明确设置 `BF_USE_EXISTING_PG_ENV=1` 时，主连接才保留既有 `GL02_PG*`；即使如此，
本地同步目标仍使用 `GL02_LOCAL_PG*`。缺少相应凭据时，正常启动会立即失败；dry-run 会跳过
依赖数据库的组件并给出警告，不会把远端密码误用于本机实例。

具体端口不要从本文复制为永久常量；以配置索引、脚本参数和现场监听三方一致为合格。

## 停止与清理

优先使用对应脚本的受控停止入口或精确 PID/命令行归属检查。不得按 `python`、`pwsh`、
`node` 名称批量结束进程，也不得清理不属于本项目的计划任务或服务。
