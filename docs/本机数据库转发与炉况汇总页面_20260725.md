```powershell
python -u tools\imes_22012_relay.py --allow-agents-password --profile all
```

```powershell

  --restart `
  --db-profile env `
  --sync-interval-seconds 0 `
  --port 8890
```

浏览器入口为 <http://127.0.0.1:8890/>。该页面自身没有登录口令；数据库凭据
只存在于本机服务进程环境中，不会下发到浏览器。

停止 8890：

```powershell
python tools\stop_local_ports_python.py --ports 8890
```

转发器使用完后应结束其 Python 进程；不得把监听地址改为 `0.0.0.0`，也不得
开放 Windows 防火墙入站。

## 3. 炉次、质量化验与传感器时间对齐

### 3.1 权威主键与时间锚点

建立一张 `heat_master`，以 IMES `public.t_ipes_cond` 为权威来源：

- 主键：`meltno`；
- 开口：`opentime`；
- 堵口：`closetime`；
- 辅助时间：`tappingtime`；
- 炉号和班次只作校验，不替代 `meltno`。

不得使用化验结果的审核、判定或发布时间作为传感器窗口终点。那些时间发生
在取样之后，用其附近传感器值会造成未来数据泄漏。

### 3.2 质量数据关联

1. 炉渣使用 `public.v_qpes_slag_insoection_final`（数据库实际拼写）或
   `public.slag_inspection`，优先按 `meltno` 精确关联。
2. 铁水化验使用 `public.v_qpes_inner_batch_insp_final_sample`。当前已实证
   试样号格式 `FYYMM-NNN-SSS` 中，`NNN` 可在同炉号、同年月和合理日期范围内
   对应正式炉次号尾段；例如 `22607-234-002` 对应
   `2#20260719-234`。`SSS` 是试样记录序号，不能擅自解释为第二包铁水。
3. 若后续取得 `heatno/meltno -> batchno -> sample` 的正式业务链，必须优先
   替换试样号派生映射。
4. 无精确炉次键的记录进入 `heat_alignment_audit`，标记
   `unmatched/ambiguous/manual_review`；不得静默按最近时间硬连。

### 3.3 每炉传感器窗口

建议同时生成三类窗口：

| 窗口 | 时间范围 | 用途 |
|---|---|---|
| `pre_tap` | `[opentime - 120 min, opentime)` | 质量预测和因果特征，首选 |
| `tapping` | `[opentime, closetime]` | 出铁过程、铁口温度和操作复盘 |
| `inter_heat` | `[上一炉 closetime, 本炉 opentime)` | 炉次间过渡分析，可选 |

133 个物理点按每炉、每窗口计算 `mean/median/min/max/std/slope`、末值、有效样本
数和覆盖率；保留点位原始 ID、中文语义、单位、质量标志和时间范围。多次铁水/
炉渣取样必须保留明细；若建模需要一炉一行，代表样本规则应明确记录为“最终
放行样”“指定序号”或“中位数”，不能悄悄覆盖前一条。

建议输出：

- `heat_master`：炉次和开堵口时间；
- `heat_hot_metal_chemistry`：铁水 C/Si/Mn/P/S/Ti 等明细；
- `heat_slag_chemistry`：炉渣 TFe/FeO/CaO/MgO/SiO2/Al2O3/TiO2、碱度等；
- `heat_sensor_window_features`：每炉三种窗口的 133 点统计特征；
- `heat_alignment_audit`：缺失、歧义、覆盖率和人工复核记录。

现有 [build_hot_metal_si_dataset.py](../tools/build_hot_metal_si_dataset.py)
已经实现铁水 Si 与炉况/传感器的无未来泄漏对齐，可作为扩展到“全铁水成分 +
炉渣 + 133 点”的基线；现有
[analyze_taphole_heat_alignment.py](../tools/analyze_taphole_heat_alignment.py)
证明出铁口温度只适合作特征和校验，不能代替 IMES 正式炉次与开堵口时间。

## 5. 炉次分析仪表盘与只读 API

启动 8890 后访问：

- 炉次仪表盘：`http://127.0.0.1:8890/heat`
- 炉次列表：`GET /api/heats?limit=24&furnace=2`
- 炉次明细：`GET /api/heat-detail?meltno=<炉次号>&window=pre_tap&group=all`
- 炉次列表导出：在 `/api/heats` 后追加 `format=csv` 或 `format=xlsx`

明细接口支持：

| 参数 | 可选值 | 说明 |
|---|---|---|
| `window` | `pre_tap`、`tapping`、`inter_heat` | 选择传感器时间窗口 |
| `group` | `core`、`static`、`body`、`all`、`custom` | 17 核心、18 静压力、80 炉体温度、全部 133 点或自选 |
| `variables` | 逗号分隔点位 ID | 仅当 `group=custom` 使用 |
| `pre_tap_minutes` | 正整数 | 调整开口前窗口长度，默认 120 分钟 |

页面显示真实炉次列表、铁水量、开堵口时间、铁水/炉渣化验、烧结矿时间背景、
传感器覆盖率与统计特征、炉况分布和关联审计。每种异步状态均有加载、空数据、
错误和重试反馈。

2026-07-26 起，铁水 Si 固定按以下口径展示：

- 列表显示每炉 `Si中位数`、有效样本数和 `最小—最大` 范围；
- 趋势图同时显示全部原始 Si 样本散点、每炉中位数曲线和最小—最大范围；
- 详情保留全部样号和元素明细，并显示有效样本数、中位数、范围和极差；
- API 每炉返回 `hot_metal_si_summary`；XLSX同时导出最后值、中位数、最小值、
  最大值和极差；
- 不删除、覆盖或静默平均原始样本；`result_ts` 仍是结果时间，不冒充取样时间。

页面详情请求使用递增请求令牌。快速切换炉次时，已经过期的旧响应不再覆盖当前
选中炉次。

## 6. 烧结矿化验的使用边界

Vastbase 确有烧结矿成分化验视图
`public.v_qpes_sinter_machine_sample_insp_final`，当前能读到 1 号和 2 号
烧结机试样。主要成分字段包括 `TFe、FeO、CaO、MgO、SiO2、Al2O3、P、S、
TiO2、MnO、Zn、Cr、R2、Mg/Al、Al/Si` 以及强度。

该视图没有 `meltno`，也没有已经核实的“烧结试样 → 料批 → 高炉炉次”业务键。
所以当前仪表盘只展示本炉开口前 12 小时内的烧结矿化验作为上游时间背景，
并固定标记：

- `alignment_method=time_context_only_not_exact_heat_lineage`
- `confidence=low`

它可以帮助观察入炉原料质量背景，但不能直接声称某一条烧结矿试样被装入了
某一炉次。要建立精确谱系，需要补齐烧结机试样、矿槽/料批、上料批次和
`meltno` 之间的正式业务键。
