# 冀南钢铁高炉智能体自学习机理（项目实现口径）

更新时间：2026-08-02

## 1. 工程定义

本项目的“自学习”不是在线修改大模型权重，也不是根据一次问答结果直接改变生产控制参数。工程上采用三层可控闭环：

1. **工况自适应**：以 `bf_sensor.one_minute_values` 为事实输入，按 5 分钟节拍重算当前工况；以最近 30 天历史分布形成 `daily_baselines`，使诊断阈值随炉况运行区间滚动更新。
2. **任务外部记忆**：把诊断快照、12 点短时诊断队列、短时总结、追问增量上下文和 MCP 工具轨迹写入数据库，下一轮研判沿用同一炉况上下文、时间窗和证据引用。
3. **受控离线迭代**：将人工确认、实际操作结果、炉次质量结果和回放误差整理为版本化样本，经过离线训练/回测、影子运行、专家复核和安全门控后，才允许更新规则、特征、知识库或模型版本。

因此，当前生产链路是“持续感知—状态重估—证据融合—只读建议—结果沉淀”；真正改变模型或规则的学习动作必须位于生产推理链路之外。

## 2. 当前项目的自学习状态机

```text
传感器 / MES / 历史 / 规程知识
          ↓
数据质量门：同步屏障、缺口、延迟、零值审计
          ↓
工况状态：60 分钟窗口 + 30 天基线 + 5 分钟诊断档位
          ↓
证据融合：规则诊断 + 基线偏离 + 趋势预测 + MCP/RAG
          ↓
智能体编排：问题解析、工具调用、短时总结、追问承接
          ↓
建议引擎：主次炉况、严重度、组合规则、安全门禁
          ↓
现场工作台：诊断 / 趋势 / 优化建议 / 问答 / 报表
          ↓
队列、总结、工具轨迹、人工确认和实际结果
          ├─→ 下一轮上下文与相似场景检索
          └─→ 受控离线样本 → 回测/影子/复核 → 版本发布
```

## 3. 核心机理

### 3.1 数据质量先于学习

同步 Watchdog、质量监测、补漏任务和零值审计先判断数据是否具备诊断资格。缺数、延迟、来源未同步或未经 pSpace 核验的零值不能直接成为“新知识”，诊断服务应降级为数据质量状态，而不是用模型补出看似合理的炉况。

### 3.2 滚动基线把运行状态变成可比较状态

对每个变量建立最近 30 天的稳健分布：

\[
z_{i,t}=\frac{x_{i,t}-\operatorname{median}_{30d}(x_i)}{\operatorname{IQR}_{30d}(x_i)+\varepsilon}
\]

生产诊断使用最近 60 分钟窗口、每 5 分钟生成一个诊断档位；基线使用 30 天窗口并按日维护。诊断引擎由当前窗口特征、基线偏离、趋势和规则共同生成 8 类炉况分数，再仲裁主炉况与次炉况。

这部分是当前系统已经具备的“自适应”：系统不是固定拿一组绝对阈值判断，而是持续吸收近期正常运行分布，更新每个变量的 `median_ref / iqr_ref / p10 / p50 / p90`。

### 3.3 多源证据不是把模型当作唯一判断器

当前炉况上下文由四类证据合成：

- **事实证据**：1 分钟物理点、当前值、数据覆盖率、来源延迟、MES 炉次和铁水质量；
- **规则证据**：full115/核心变量特征、8 类炉况分数、主次炉况和基线对比；
- **预测证据**：Chronos 单目标、多关键 `past_covariates`、目标专属上下文窗口和未来 120 分钟预测；
- **知识与工具证据**：三规二制/专家知识库的分层检索，以及 MCP 目录发现、统计、趋势和相关性工具。

大模型负责在已授权上下文内做问题理解、工具编排和语言化总结；不绕过数据库质量门、规则诊断或 MCP 参数校验自行编造生产事实。

### 3.4 建议输出必须经过安全门禁

建议不是模型自由生成的操作指令，而是：

\[
R_t=\operatorname{Format}\left(\operatorname{SafetyGate}\left(
\operatorname{Combination}\left(\operatorname{Template}(D_t)\right)\right)\right)
\]

其中 `D_t` 是当前诊断快照。引擎先按主炉况选择动作模板，再处理主次炉况组合、严重度和安全约束，输出即时动作、后续动作、禁止动作、观察项和安全警告。当前引擎为只读建议，不连接生产控制写接口；现场人员必须依据制度确认执行。

### 3.5 学习结果分为“马上可用”和“审核后可用”

**马上可用**的内容包括：

- 新的 5 分钟诊断快照和 12 点短时队列；
- 当前队列的短时大模型总结；
- 同一会话的追问增量、已调用工具和证据引用；
- 每日更新的 30 天基线和数据质量状态。

**审核后可用**的内容包括：

- 人工确认的主/次炉况与误判原因；
- 实际操作后的炉况变化、铁水 Si/质量结果和班次复盘；
- 新增或修订的三规二制条款、专家案例和动作模板；
- 规则阈值、特征工程、Chronos 模型或 Si 预测模型的新版本。

后者必须经过“样本门禁 → 时间外回测 → 影子运行 → 专家复核 → 版本发布”，不能由生产页面的单次问答直接写回模型。

## 5. 可直接用于论文或汇报的结论段

冀南钢铁高炉智能体采用面向连续生产的受控自学习机制。系统以分钟级传感器、MES 炉次质量、历史诊断和三规二制知识为输入，先经过数据同步、覆盖率、延迟和零值审计，再以 60 分钟当前窗口和 30 天滚动基线构造可比较的工况状态；规则引擎、趋势预测、MCP 工具和分层知识检索共同形成多源证据，领域大模型在受控上下文中完成任务编排和解释，建议引擎进一步通过主次炉况组合、严重度映射与安全门禁生成只读辅助决策。诊断队列、短时总结、追问增量和工具轨迹形成外部记忆，支持相似工况承接；经现场确认的操作结果和质量反馈则进入版本化离线样本，经时间外回测、影子运行和专家复核后更新规则、特征、知识库或模型。由此形成“实时感知—状态自适应—证据融合—安全建议—结果沉淀—受控迭代”的闭环，而不是未经审核的在线自动控制。
