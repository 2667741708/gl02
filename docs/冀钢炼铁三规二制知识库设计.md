# 冀钢炼铁三规二制知识库设计

## 文档含义与范围

“三规二制”用于把炼铁岗位的安全、操作、设备和协同要求固化成可执行制度：

- 三规：安全操作规程、技术/工艺操作规程、设备使用维护规程。
- 二制：岗位交接班制度、生产联系确认制。

本文件目录包含 28 个一级对象：前 26 个为高炉工长、高炉炉前工、看水工、热风工、上料、渣处理、除尘、TRT、鼓风机、水泵、空压机、喷煤、铸铁、维修、电气、仪表等岗位；第 27、28 项分别为岗位交接班制度和生产联系确认制。转换后的文档共有 4,934 个段落、122 个表格。

这类文档与事故问答不同。事故问答适合“一问一答一块”，三规二制则必须同时保留岗位、规程类型、编号章节和原子条款，否则只按固定字数切分会把 5.1.1 与 5.1.1.1 等上下级关系切断。

## 层级模型

固定层级为：

```text
文档
└─ 岗位或制度（1-28）
   └─ 规程类型（三规/二制）
      └─ 编号章节（如 5、5.1、5.1.1）
         └─ 原子条款（如 5.1.1.1）或表格
```

每个知识块都保存：岗位/制度、规程类型、章节编号、完整层级路径、原文块起止位置和内容哈希。标题样式不可靠时，以目录名称、岗位编号和正文编号共同识别；原文件中的表格按行转成可检索文本，但保留表格块类型。

## 多粒度 chunk

### atomic

一个原始段落或一张表格形成一个细粒度块，用于查询具体阈值、禁令、条件、操作次序和单条职责。当前生成 4,540 个。

### topic

把同一直接父编号下的兄弟条款合并。例如高炉工长 `5.1.1 风量` 的 `5.1.1.1-5.1.1.7` 合并为一个 topic，保留原文次序，单块目标不超过约 1,800 字。当前生成 805 个。

### section

按“岗位/制度 + 规程类型”聚合并分片，适合回答“概述高炉工长技术操作规程”“热风工设备维护重点”等宽问题，单块目标不超过约 2,600 字。当前生成 109 个。

本次共生成 5,454 个层级块。三种粒度并存是有意设计：精确问题优先 atomic，章节问题优先 topic，岗位概述优先 section；后续融合排序时应对完全相同的原文做去重，避免三个粒度同时进入模型上下文。

## PostgreSQL 表

本机原生 PostgreSQL 16 已创建：

```text
bf_assistant.rag_hierarchical_chunk
```

核心字段：

| 字段 | 含义 |
|---|---|
| `chunk_id` | 稳定知识块 ID |
| `doc_id` | 文档 ID，本文件为 `bf_three_rules_two_systems_20260712` |
| `title` | 可读层级标题 |
| `content` | 原始条款或聚合原文 |
| `enriched_content` | 注入岗位、规程、路径和粒度后的向量文本 |
| `granularity` | `atomic`、`topic`、`section` |
| `chapter_code/chapter_title` | 1-28 岗位或制度 |
| `regulation_type` | 三规或二制类型 |
| `section_code` | 章节编号，如 `5.1.1` |
| `hierarchy_path_json` | 完整编号路径 |
| `source_block_start/end` | 原文块定位 |
| `content_hash` | 原文一致性校验 |

当前本机验收结果：5,454 行、28 个岗位/制度、5 种规程/制度类型；atomic/topic/section 分别为 4,540/805/109。
