# 8093 Billboard 悬停抖动修复（2026-08-02）

## 问题定义

- 缺陷编号：`BUG-BF3D-8093-TOOLTIP-JITTER-SINGLE-OWNER-20260802`。
- 用户现象：鼠标停在密集点位附近时，详情广告牌在多个位置间上下左右颤动，内容也可能反复切换。
- 正式名称：Tooltip jitter、hover flapping、hit-test thrashing；本页同时存在坐标空间写入冲突。

## 已确认根因

8093 页面同时保留了原始鼠标跟随写入器、平滑修补写入器和局部坐标修补写入器。它们共同修改同一个 `.cad-furnace-tooltip`，但分别使用视口坐标和容器相对坐标。密集命中球重叠时，最近点又会逐帧切换，最终形成位置、内容和左右放置方向的竞争。

这不是 GPU 卡顿、Three.js Sprite 朝向抖动，也不是 WebSocket 数值刷新造成的。

## 修复合同

- 8093 专用运行时：[bf3d-tooltip-stable-hover-8093.js](../高炉前端数据/assets/bf3d-tooltip-stable-hover-8093.js)。
- 单一控制器独占目标选择、内容、显示/隐藏和位置；旧平滑与局部修补在 React 渲染前退出。
- 坐标统一为 `position: fixed` 的浏览器视口坐标；tooltip 锚定 Billboard 投影点，不跟随鼠标游标。
- 进入半径 `30px`、退出半径 `46px`、切换优势量 `12px`、候选驻留 `140ms`。
- 左右放置方向在点位激活时确定；同一激活点不因边缘临界值逐帧翻转。
- 位置只由 `requestAnimationFrame` 和相机 `change` 事件更新；不使用周期定时器写位置。
- 相机拖拽时隐藏 tooltip，OrbitControls 全炉旋转不受影响；点位聚焦继续关闭。
- 当前 121 个物理/设备测点和左侧 28 变量面板均不改变。
- 冷启动时只有 `install(viewer)` 真正返回清理函数后才登记 `installedViewer`；适配器或 React DOM 尚未就绪时继续重试。
- 专用模块可能先于 Babel 应用设置单写入者标志，故模块不得在顶层做一次性退出判断；它必须持续短轮询，并在安装阶段同时等待标志和 viewer 就绪。
- 远端 viewer 不暴露 `viewer.THREE`，运行时从 `viewer.camera.position.clone()` 取得 Vector3，避免依赖未公开命名空间。
