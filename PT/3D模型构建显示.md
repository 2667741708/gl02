> - 状态：历史设计总览（2026-07-24 基线）
> - 当前入口：[GL02 点位与资产索引](../docs/GL02高炉3D传感器点位清单索引.md)、
>   [8093/8094 三维相关记录](../docs/handoffs/)
> - 适用边界：保留建模与分层思路；当前页面合同、Billboard、相机和部署方法以 `docs/` 最新记录为准。

## 1. 目标与结论

本文对应问题编号 `Q-3D-001`，目标包括：

1. 将 Three.js 高炉查看器制作成可部署、可复制的浏览器构建产物；
2. 让局域网或授权网络内的其他电脑通过 HTTP(S) 地址查看模型，无需安装 Node.js、Three.js 或 CAD 软件；
3. 支持按炉体工艺段和炉体温度层筛选、隔离、半透明及剖切显示；
4. 选中某一层后，仅显示该层炉体和该层传感器，并查看点位实时值、状态及趋势入口；
5. 对不支持 WebGL 或显卡能力不足的电脑提供明确降级画面，而不是空白页面。

结论：方案可实施。当前 GLB 已经包含 115 个独立传感器节点，按第 7～16 层过滤传感器可以直接在前端完成；但当前炉壳是一个整体网格，尚未按“炉身、炉腰、炉腹、炉缸”拆成独立炉体网格。若要真正单独选中、隐藏或导出每个炉体段，需要对源模型做一次离线几何切分或重新建模导出。

“构建产物”能够解决依赖、资源路径和跨电脑部署一致性问题，但不能让完全不支持 WebGL 的电脑强制运行 3D。浏览器端仍依赖 WebGL、显卡驱动和可用的图形上下文，因此必须同时实现能力检测与静态图降级。

### 2.1 GLB 内部结构审计结果

2026-07-16 对 GLB JSON chunk 做只读审计，结果如下：

- glTF/GLB 版本：2.0；
- `asset.generator`：`gl02-cad-generator high-detail visual builder`；
- 场景：1；
- 节点：174；
- 网格：25；
- 材质：23；
- 传感器节点：115，均使用 `SENSOR_<变量ID>` 命名；
- 贴图和内嵌图片：0，当前工业质感主要由页面侧 PBR 纹理配置补充；
- 动画：0；
- 未声明必需 glTF 扩展，兼容风险相对较低。

115 个传感器节点是独立节点，但共用 `sensor_pick_marker_sphere` 网格，适合按点位、类别和层号进行显隐及着色。非传感器部分已经包含炉壳、加强圈、冷却带、平台、支撑、围管与风口、两个出铁口、上升管、炉顶设备、料柱、软熔带、铁水池和渣层等语义网格。

当前关键限制是：炉壳节点只有 `APPROX_GL02_furnace_shell`，没有 `FURNACE_SHAFT`、`FURNACE_BELLY`、`FURNACE_BOSH`、`FURNACE_HEARTH` 或第 7～16 层对应的独立炉壳网格。因此：

- 设备级显隐：当前即可实现；
- 传感器按层显隐：当前即可实现；
- 用裁剪平面观察某一高度带：当前即可实现；
- 真正选择并隐藏某一个独立炉体段：必须先切分炉壳网格；
- 每一温度层都有独立“环形炉壳实体”：当前模型不具备，需要生成。

## 4. 炉体拆分与分层显示设计

### 4.1 两套层级必须分开

炉体显示需要同时支持两种不同概念：

1. **工艺段**：炉喉、炉身、炉腰、炉腹、炉缸；
2. **传感器安装层**：第 7～16 层及 A～H 方位点。

工艺段用于理解炉体结构；传感器层用于现场查看同一标高的一圈温度。两者不能混为一个字段。建议内部标识如下：

```text
FURNACE_THROAT
FURNACE_SHAFT
FURNACE_BELLY
FURNACE_BOSH
FURNACE_HEARTH

SENSOR_LAYER_L07 ... SENSOR_LAYER_L16
SENSOR_AZIMUTH_A ... SENSOR_AZIMUTH_H
```

### 4.2 已知温度层与点位

页面当前已有第 7～16 层炉体温度定义，每层 A～H 共 8 个点，合计 80 个炉体温度点：

| L8 | 炉腹上 | 18.335 m | `T_body_L8_A`～`T_body_L8_H` |
| L9 | 炉腰 | 20.125 m | `T_body_L9_A`～`T_body_L9_H` |
| L10 | 炉身下 | 21.860 m | `T_body_L10_A`～`T_body_L10_H` |

### 4.3 推荐的模型拆分方式

推荐保留一个 GLB 文件，在一个场景树中提供独立命名节点，而不是为每层复制一个完整 GLB。这样可以减少网络请求、重复几何和浏览器显存占用。

目标场景树建议为：

```text
GL02_FURNACE
├─ STRUCTURE
│  ├─ FURNACE_THROAT
│  ├─ FURNACE_SHAFT
│  ├─ FURNACE_BELLY
│  ├─ FURNACE_BOSH
│  └─ FURNACE_HEARTH
├─ EQUIPMENT
│  ├─ BUSTLE_PIPE
│  ├─ TUYERE_STOCKS
│  ├─ TAPHOUSE_01
│  ├─ TAPHOUSE_02
│  └─ TOP_EQUIPMENT
├─ SENSOR_LAYERS
│  ├─ SENSOR_LAYER_L07
│  │  ├─ SENSOR_T_body_L7_A
│  │  └─ ... SENSOR_T_body_L7_H
│  └─ ... SENSOR_LAYER_L16
└─ PROCESS_VISUALS
   ├─ COHESIVE_ZONE
   ├─ MOLTEN_IRON
   └─ SLAG
```

### 4.4 三种实施路径

#### 路径 A：前端虚拟分层，最快可用

- 不修改当前 GLB；
- 根据传感器 ID 的 `L7`～`L16` 解析层号；
- 选择一层后，只显示该层 8 个传感器；
- 用两个水平 `THREE.Plane` 裁剪整体炉壳，只保留该层上下边界间的薄片；
- 其他炉体以低透明度上下文显示，或完全隐藏；
- 适合作为第一阶段交付。

优点是改动小、可快速验证。限制是裁剪后得到的是显示效果，不是独立、可导出的单层实体；透明材质和双裁剪面对部分低端显卡也会增加负担。

#### 路径 B：离线切分当前炉壳，推荐生产方案

- 使用 Blender Python、FreeCAD Python/OpenCascade 或可信 CAD 工具读取 STEP/GLB；
- 以经现场确认的工艺段分界和传感器层中点为切割平面；
- 把整体炉壳切成工艺段网格，并按需生成 L7～L16 对应的环形显示薄片；
- 保留原世界坐标、单位、法线、材质和传感器位置；
- 重新导出一个带清晰节点树的 GLB；
- 运行自动校验，确认 115 个传感器没有丢失或漂移。

该路径能够真正做到独立拾取、显隐、描边和爆炸视图，是推荐的正式方案。

#### 路径 C：回到权威 CAD/BIM 重新分组导出

如果能够取得带装配树的原始 CAD/BIM，应优先在源模型中按照炉喉、炉身、炉腰、炉腹、炉缸和设备系统分组，然后导出 glTF/GLB。该路径语义和尺寸最可靠，但需要模型制作方和现场专业人员参与确认。

## 5. 浏览器交互方案

### 5.1 正式控件

在 3D 查看区增加真实可操作控件：

- “全部”“炉身”“炉腰”“炉腹”“炉缸”工艺段切换；
- “L7”～“L16”传感器层切换；
- “仅显示本层”“上下文半透明”“剖切查看”三种显示模式；
- A～H 方位筛选；
- “恢复视角”“正视”“俯视”“剖面”相机按钮；
- 传感器颜色图例：正常、关注、告警、无数据；
- 点位搜索和定位；
- 当前层点位表，显示点名、实时值、单位、时间、质量状态；
- 单击点位打开详情，提供“查看趋势”“查看诊断”的实际路由入口。

所有异步状态必须覆盖 `loading / empty / error / ready`；模型加载失败时显示“重新加载”和具体原因。不能只留空白画布。

### 5.2 传感器绑定规则

加载完成后建立一次索引，不应每帧遍历整棵场景树：

```text
sensorById: Map<sensorId, Object3D>
sensorsByLayer: Map<L07..L16, Object3D[]>
sensorsByCategory: Map<category, Object3D[]>
partsByProcessZone: Map<zone, Object3D[]>
```

点位层号可由 `T_body_L(7..16)_[A-H]` 解析，但长期应增加独立配置清单，明确 `sensor_id`、`layer_id`、`zone_id`、`elevation_m`、`azimuth`、`model_node` 和数据源字段，避免业务规则散落在 UI 正则表达式中。

选择 L9 的预期结果示例：

1. 炉腰或 L9 对应切片高亮；
2. 只显示 `SENSOR_T_body_L9_A`～`SENSOR_T_body_L9_H`；
3. 相机对准该层中心；
4. 右侧表格显示 8 个点实时值、状态和时间；
5. 悬浮与点击只命中当前可见点；
6. 无数据点保持可见但显示灰色及“暂无有效数据”，不得伪造数值。

## 6. 可部署构建产物方案

### 6.1 当前构建问题

[`front2/package.json`](../高炉前端数据/front2/package.json#L6-L16) 虽然已经依赖 Vite，但当前 `npm run build` 实际执行的是 `python verify_front2_static.py`，只做静态契约检查，并没有生成 `dist`。因此需要增加真正的生产构建入口，同时保留现有检查命令。

建议脚本职责调整为：

```json
{
  "scripts": {
    "check": "python verify_front2_static.py",
    "build": "npm run check && vite build",
    "preview": "vite preview --host 0.0.0.0"
  }
}
```

正式实施时应把当前大 HTML 中的查看器提取为可构建模块，Three.js 作为 npm 依赖或受版本锁定的本地依赖进入 bundle。GLB、Logo、工业纹理和场景配置放入 Vite `public` 或通过资源导入复制到构建目录。

### 6.2 推荐发布目录

```text
dist/
├─ index.html
├─ assets/
│  ├─ app.<hash>.js
│  └─ app.<hash>.css
├─ models/
│  ├─ gl02_blast_furnace.glb
│  └─ model_manifest.json
├─ textures/industrial/
├─ config/
│  ├─ industrial_furnace_scene.json
│  └─ furnace_layers.json
├─ logo/
└─ fallback/
   └─ gl02_furnace_preview.webp
```

`model_manifest.json` 应记录模型版本、文件 SHA-256、字节数、节点数、网格数、传感器数、坐标单位、生成时间和来源状态。浏览器加载前可以检查版本，服务端部署后可以核对资源是否完整。

### 6.3 部署方式

- 生产推荐：Nginx、IIS 或现有 8092 后端托管 `dist`；
- 监听地址：服务端监听 `0.0.0.0`，客户端通过服务器 IP/域名访问；
- 网络：只开放授权网段需要的端口，优先使用 HTTPS；
- MIME：`.glb` 返回 `model/gltf-binary` 或 `application/octet-stream`，JS Module 返回正确 JavaScript MIME；
- 缓存：带 hash 的 JS/CSS 可长期缓存，模型按版本文件名或 manifest 进行缓存更新；
- 不支持直接双击 `index.html`，必须通过 HTTP(S) 访问，避免 `file://` 下 ES Module、CORS 和模型加载限制；
- 若页面保留实时数据、问答、WebSocket 和趋势功能，静态 `dist` 之外仍需要 8092 API 与 8767 WebSocket 服务，且前端 API/WS 地址必须配置为客户端可访问的服务器地址，不能写死 `127.0.0.1`。

## 7. 跨电脑兼容与降级策略

加载顺序建议：

```text
检测 WebGL2
  → 可用：正常或高质量模型
  → 不可用：检测 WebGL1
      → 可用：低画质模型
      → 不可用：静态炉体图 + 点位表
```

低画质模式应自动执行：

- 关闭抗锯齿和阴影；
- `pixelRatio` 限制为 1；
- 关闭高成本透明叠加、后处理和持续动画；
- 采用按需渲染；
- 可选加载简化 LOD 模型；
- 保留点位表和实时数据，不让图形能力影响业务数据可达性。

还要监听 `webglcontextlost` 与 `webglcontextrestored`。加载错误至少区分：模型 404、GLB 解析失败、WebGL 不可用、显存不足、上下文丢失和实时数据连接失败。

- 内切面切掉一半炉壳，并启用暖/冷补光和大量发光内部对象，剩余炉壳不再是视觉主体；
- 之前质感明显的 P40 图是近距离棚拍，并且隐藏了全部内部工艺示意对象。

材质目标应区分两个表面：

- 外表面：风化喷涂钢壳，增加板片、焊缝、氧化、积灰、涂层剥落和密集微点蚀；可以接近砂粒/橘皮触感，但不能把钢壳整体做成水泥；
- 剖切内表面：单独建立冷却壁、耐火砖/碳砖、浇注料与保护层，这里才使用更明显的砖缝、砂粒、孔隙和烧蚀粗糙度。

下一轮应先修正工艺语义和浏览器光照/尺度，再决定是否增强 Normal；否则直接把法线强度拉高会造成旋转闪烁、远景噪点和“水泥化”失真。完整决策见[总设计详细规划 18.6](高炉3D模型/总设计详细规划.md#186-内切面语义与微表面质感偏差审计)。
