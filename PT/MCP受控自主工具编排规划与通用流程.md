# MCP 受控自主工具编排规划与通用流程

需求编号：`REQ-MCP-AGENT-ORCHESTRATION-20260726`

## 1. 目标

让模型能够结合当前问题和多轮对话，自主判断是否需要查询数据、检索传感器目录、
执行统计计算或生成图表；所有实际调用必须经过服务端白名单、JSON Schema、参数
规模、轮数和只读边界校验。

模型负责“理解和规划”，MCP 负责“确定性执行”，服务端负责“安全治理”。

## 2. 非目标

- 不允许模型生成并执行任意 SQL。
- 不允许模型取得数据库账号、密码、连接串或内部 schema 控制权。
- 不新增生产控制写入工具。
- 不删除现有高频口语固定路由；固定路由继续作为低延迟快速通道。
- 不把模型生成的变量名直接当作可信数据库字段。

## 3. 五阶段流程

```text
阶段一：工具标准化
  ↓
阶段二：目录发现与语义解析
  ↓
阶段三：模型多轮规划
  ↓
阶段四：服务端策略校验与确定性执行
  ↓
阶段五：结果归纳、证据返回与可追踪记录
```

### 3.1 工具标准化

MCP 只暴露有明确 JSON Schema 的只读业务工具，主要能力包括：

- 传感器目录检索与元数据查询；
- 单点/多点最新值、历史值和统计值；
- 趋势图、相关图、分布图和炉体温度矩阵图；
- 工艺增强统计；
- 炉次铁水、炉渣和进料化学成分查询；
- 日报与历史问答检索。

### 3.2 目录发现

模型遇到非标准名称、层高、方位、口语别名或不确定变量时，先调用目录工具。
目录返回标准变量、别名、单位、点位、能力和状态。后续查询只能使用目录确认的
标准变量，最终仍由 MCP 的 `resolve_variable()` 再次校验。

### 3.3 多轮规划

后端把最近对话和工具定义一起交给模型。模型可在限定轮数内执行：

```text
查目录 → 查历史 → 做计算 → 生成图 → 总结
```

追问中的省略信息可以继承最近对话。例如：

```text
用户：看看最近半小时炉顶压力。
用户：和总压差比较，有没有相关性？
用户：画出来。
```

后两轮应复用 `P_top`、`DP_total` 和最近 30 分钟，不要求用户重复描述。

### 3.4 服务端治理

每次工具调用执行前必须经过：

1. 工具名必须在当前 MCP `list_tools` 白名单；
2. 参数必须是 JSON 对象；
3. 必填字段必须存在；
4. 不允许 Schema 未声明的参数；
5. 参数基本类型必须与 Schema 一致；
6. 字符串、数组和单轮调用数量必须受限；
7. 工具调用总轮数和总次数必须受限；
8. 具体变量、时间窗、查询点数、聚合方式继续由 MCP 函数二次校验；
9. 校验失败作为结构化工具错误返回模型，允许模型修正一次；
10. 全程只读，不把 SQL、凭据或生产写能力暴露给模型。

### 3.5 结果与追踪

最终回答必须优先使用工具事实，说明变量、时间范围、数据时间、有效样本数、
缺失情况和图表地址。工具轨迹至少记录：

- 规划来源：固定快速路由、确定性图表路由或模型规划；
- 工具名和经过净化的业务参数；
- 校验结果；
- 执行轮次；
- 结果摘要或结构化错误；
- 是否因轮数/次数上限终止。

## 4. 混合路由策略

```text
高置信度固定口语
  → 直接预取或确定性图表调用

多变量、计算、比较、关联、追问或陌生表达
  → 模型自主规划 MCP 工具

模型提交工具调用
  → 服务端统一校验

变量仍不唯一
  → 目录检索或向用户追问
```

固定路由不是模型自主能力的替代品，而是生产高频查询的缓存式快速通道。

## 7. 验收标准

1. 纯知识问题不强制查询数据库。
2. 高置信度单点问题继续走固定预取快速通道。
3. “分析最近两小时顶压和总压差的关系并画图”由模型选择目录、历史/分析或
   绘图工具，不依赖为整句话编写固定模板。
4. 多轮追问可以利用对话中已有变量和时间范围。
5. 未知工具、缺失必填参数、额外参数、错误类型、超长参数、超次数调用均被
   服务端阻止，且不会进入 MCP 执行。
6. MCP 仍对变量、时间窗、查询规模和枚举参数进行二次校验。
7. 工具失败可作为结构化结果交回模型修正，不因单点失败导致整个问答崩溃。
8. 本地单元测试、原有 MCP 回归、8093/8094 现网口语验收全部通过。
9. 发布时只重启问答代理，8768 实时数据服务不得重启。

## 8. 可复用项目方法

这套流程可抽象为：

```text
定义业务工具
→ 建立业务对象目录
→ 给模型上下文和工具 Schema
→ 在服务端验证模型计划
→ 由确定性服务执行
→ 把结果交回模型继续规划
→ 形成可审计回答和测试
```

迁移到其他项目时，只替换“业务对象目录”和“确定性工具实现”，编排治理层、
多轮循环、测试方法和追踪结构可以复用。
