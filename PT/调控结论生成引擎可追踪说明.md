# 调控结论生成引擎可追踪说明

本文档给 PT 文件夹提供一份现场交接口径：完整建议引擎已经以独立代码目录落地，8767 会在最新诊断快照上生成标准 `recommendation`，前端只负责展示，不再自行编造动作分数。

## 一、现状结论

- 独立代码目录：`调控结论生成引擎`。
- 当前没有另建 `suggestionengine` 目录；后续如需英文命名，建议只在文档中注明别名，不复制第二套代码。
- 8767 接入点：`自动诊断服务\local_pg_ws_bridge.py` 调用 `自动诊断服务\recommendation_adapter.py`。
- 引擎版本：`v4-complete`。
- 安全边界：只生成只读建议，不写生产控制、不直接操作现场设备。

## 二、原始契约

完整建议引擎包含：

1. 八类动作模板：`normal`、`lowline`、`edge`、`center`、`channel`、`cold`、`hot`、`column`。
2. 严重度分级：按主诊断分数映射建议等级与复查周期。
3. 主/次炉况组合规则：目前覆盖低料线+炉凉、边缘+炉凉等组合修正。
4. 安全门禁：高压、悬料、顶温、风口、TRT 相关安全约束。
5. 标准输出：目标、立即动作、后续动作、禁止动作、观察项、复查周期、现场确认、安全警示和只读元数据。

## 四、8767 输出检查

最新诊断 payload 中应出现：

```json
{
  "recommendation_status": {
    "state": "ready",
    "engine": "blast_furnace_recommendation_engine",
    "version": "v4-complete"
  },
  "recommendation": {
    "goal": "...",
    "immediate_actions": [],
    "followup_actions": [],
    "forbidden_actions": [],
    "observe_items": [],
    "safety_gate_passed": true,
    "engine_meta": {
      "read_only": true
    }
  }
}
```

如果 `recommendation_status.state=failed`，前端不能自行补造标准建议，应显示错误或降级状态，并优先检查引擎目录、Python 导入路径和诊断快照字段。

## 五、快速验证

```powershell
$OutputEncoding=[Console]::OutputEncoding=[Text.UTF8Encoding]::new($false)
python tools\verify_8093_recommendation_engine_contract.py
```

预期：8 类炉况、组合规则、安全门禁、8767 payload 和前端绑定测试通过。

## 六、变更注意

- 修改模板或门禁时，必须同步改 `docs\调控结论生成引擎可追踪说明.md` 和本文。
- 修改 8767 字段时，必须同步改前端读取逻辑和契约测试。
- 前端优化建议页不得再显示旧的动作固定分数、风险贡献或手造建议。
- 安全门禁只能输出提示、禁止项和强制复核项，不能新增生产控制写入。
