# 调控结论生成引擎可追踪说明

本文档给 PT 文件夹提供一份现场交接口径：完整建议引擎已经以独立代码目录落地，8767 会在最新诊断快照上生成标准 `recommendation`，前端只负责展示，不再自行编造动作分数。

## 一、现状结论

- 独立代码目录：`调控结论生成引擎`。
- 当前没有另建 `suggestionengine` 目录；后续如需英文命名，建议只在文档中注明别名，不复制第二套代码。
- 8767 接入点：`自动诊断服务\local_pg_ws_bridge.py` 调用 `自动诊断服务\recommendation_adapter.py`。
- 本地引擎版本：`v5-three-rules-two-systems`；尚未部署远端 8768/8093。
- 安全边界：只生成只读建议，不写生产控制、不直接操作现场设备。

## 二、原始契约

完整建议引擎包含：

1. 四类策略：上部、下部、负荷、碱度；八类诊断标签只负责触发候选和目标。
2. 四态合同：`eligible / blocked / needs_data / manual_confirm`。
3. 通用主次组合：任意主、次炉况合并，不再只写两个组合规则。
4. 顺序与冲突：热制度上下行动作链、相反方向冲突和安全优先级。
5. 标准输出：每条动作都带原文章节、证据、前置、阻断、幅度、顺序、缺失数据、观察窗口、审批和只读标记；同时保留旧三组数组。

## 四、8767 输出检查

最新诊断 payload 中应出现：

```json
{
  "recommendation_status": {
    "state": "ready",
    "engine": "blast_furnace_recommendation_engine",
    "version": "v5-three-rules-two-systems"
  },
  "recommendation": {
    "schema_version": "three_rules_two_systems.v1",
    "actions": [],
    "goal": "...",
    "immediate_actions": [],
    "followup_actions": [],
    "forbidden_actions": [],
    "observe_items": [],
    "safety_gate_passed": true,
    "engine_meta": {
      "read_only": true
    }
  }
}
```

如果 `recommendation_status.state=failed`，前端不能自行补造标准建议，应显示错误或降级状态，并优先检查引擎目录、Python 导入路径和诊断快照字段。

## 六、变更注意

- 修改模板或门禁时，必须同步改 `docs\调控结论生成引擎可追踪说明.md` 和本文。
- 修改 8767 字段时，必须同步改前端读取逻辑和契约测试。
- 前端优化建议页不得再显示旧的动作固定分数、风险贡献或手造建议。
- 安全门禁只能输出提示、禁止项和强制复核项，不能新增生产控制写入。

## 七、八炉况与模型复核扩展（2026-08-05）

- 8767 新增 `recommendation_bundle`；`active_plan` 是当前有效方案，`conditions` 固定覆盖八类炉况。
- 非当前炉况只能显示 `supporting/hypothetical` 条件预案，不能加入当前执行队列。
- 页面可恢复查看每条动作的十类审计字段和四种状态；切换炉况时证据、曲线和详情上下文同步切换。
- `POST /api/diagnosis/model-review` 只复核规则分数，失败或停止不影响规则建议；模型无权修改动作、幅度、顺序、门禁和审批。
- 本地合同及 Chromium 九视口已通过；远端 8093/8768 未在本轮部署或重启。
