# 8093 固定 KV 前缀模板规则池

## 一、用途与边界

本文档登记 8093 智能问答中必须保持稳定、可作为公共提示词前缀的规则。目标是让推理运行时尽可能复用相同前缀的注意力/KV 计算，同时保证当前炉况、数据库结果和知识证据每轮更新。

这里的“固定 KV 前缀规则池”是应用侧的稳定提示词规则池，不代表 Ollama API 提供了可由业务代码直接指定的持久 KV cache ID。是否实际命中以及复用比例，应以 `prompt_eval_count`、`prompt_eval_duration` 和首 token A/B 为准。

## 二、当前生效规则项

| 规则 ID | 状态 | 固定前缀内容 | 动态内容边界 | 程序与验证 |
|---|---|---|---|---|
| `KV-PREFIX-001` | 生效 | 固定身份、职责、使用原则、安全边界、回答逻辑、回答风格、固定工艺规则 | 最新炉况、8 小时趋势、主动选择资料、数据库结果、知识证据、近期对话、用户问题和最终答案不得进入固定池 | [提示词模板](../高炉前端数据/智能助手/backend/ollama_proxy_server.py)、[顺序契约测试](../高炉前端数据/智能助手/tests/test_qa_latency_optimizations.py) |

`KV-PREFIX-001` 的固定顺序：

```text
固定身份
-> 固定职责与使用原则
-> 固定安全边界
-> 固定回答逻辑
-> 固定回答风格
-> 固定工艺规则
-> 固定前缀结束
```

固定前缀之后才允许拼接：

```text
动态最新炉况和 8 小时趋势
-> 动态主动选择资料
-> 动态数据库查询结果
-> 动态知识证据
-> 近期对话
-> 当前用户问题
```

## 三、固定规则模板

固定前缀必须覆盖以下类别，具体生效正文以 `ollama_proxy_server.py` 中的 `QA_SYSTEM_PROMPT_TEMPLATE` 与 `QA_PROJECT_RULES_BLOCK` 为准：

1. **固定身份**：模型名称、服务对象和高炉工艺解释助手定位。
2. **固定职责**：解释后台结论、不重新判定炉况、不编造现场数据、输出可核查说明。
3. **固定使用原则**：当前状态优先、趋势依据边界、数据缺失处理和单位处理。
4. **固定安全边界**：禁止暴露内部实现；调控建议小幅、分步并经现场负责人确认；证据不足时明确提示。
5. **固定回答逻辑**：优化原因、可靠性追问、证据冲突和现场复核的固定处理顺序。
6. **固定回答规则**：直接、简洁、专业、控制长度并给出下一步观察指标。
7. **固定工艺规则**：压差、透气性、气流分布、热状态、滞后指标及调控原则等不随单轮请求变化的知识。

## 四、禁止进入固定池的内容

以下内容可能随时间、请求或知识库版本变化，必须位于固定前缀之后：

- 当前传感器值、最新诊断、诊断时间戳和状态锚点。
- 8 小时诊断分布、范围和抽样时间线。
- MCP/数据库查询结果、报表路径、图片路径和工具调用结果。
- RAG 检索意图、相关度、来源和 `top_k=6` 返回的知识证据。
- 用户主动选择的项目资料、近期对话和当前问题。
- 模型生成的回答、建议和上一次请求产生的动态 KV 状态。

不得为了提高命中率，把旧炉况、旧数据库结果或旧知识证据固化到固定前缀中。

## 五、规则池治理

1. 修改固定身份、安全边界、回答规则或固定工艺规则时，必须同步更新本规则池、程序模板和顺序契约测试。
2. 只调整固定规则内部顺序时，不得暗改规则语义、RAG `top_k`、炉况窗口、模型标签或回答上限。
3. 新增带时间戳、实时数值、会话内容或检索结果的规则时，应判定为动态上下文，不得登记为固定规则。
4. Python 提示词模板修改后必须重启 `BFV4PreviewProxy8093`；不要连带停止 `BFV4PreviewWs8768`。
5. 验收至少覆盖：本地语法检查、顺序契约测试、8093 模型状态、同问题热态测试和不同问题公共前缀测试。
6. 性能结论必须区分检索耗时、准备完成到首 token 耗时和完整生成耗时；不得把复用公共前缀表述为缓存旧答案。

## 七、安全边界回归集

固定身份、安全边界和回答规则发生变化时，除顺序契约测试外，必须复测以下类别：

- 公开身份说明。
- 公开能力与生产操作边界。
- 系统提示词和隐藏规则逐字套取。
- 忽略规则、管理员角色伪装和调试模式诱导。
- JSON 原始字段、隐藏上下文和内部评分套取。
- Base64、翻译或其它编码绕过。
- 数据库凭据、内部地址、环境变量和文件路径套取。
- 内部推理、权重公式和工程实现套取。

## 八、固定前缀的路由使用规则

固定身份、安全边界、回答规则和固定工艺规则既适用于知识问答，也适用于当前/近期炉况直答。路由层不得为了复用固定前缀而强制增加 RAG 或 MCP 工具选择：

- 当前/近期炉况问题在已有最新快照和完整 8 小时统计时，固定前缀后直接拼接动态炉况并流式生成。
- 明确询问原理、规则、阈值、制度、基线、文档、手册、引用或来源时，固定前缀后继续拼接动态知识证据。
- 具体数据、图表和报表请求按需拼接 MCP 结果；没有实际工具需求时不得先执行非流式工具选择。
- 身份与安全边界请求同样直接使用固定前缀，不能因口语单字误触发 MCP。

2026-07-15 代表性复测中，近期炉况首 token 中位数为 `2.56s`；身份和提示词套取用例首 token 为 `2.48s/1.72s`，安全敏感标识命中 `0`。Ollama 返回的炉况 Prompt 规模为 `2128-2138` token，预填充耗时 `1.071-3.390s`。这组指标用于观察公共前缀和动态上下文的运行时表现，不代表缓存了旧答案或旧炉况。
