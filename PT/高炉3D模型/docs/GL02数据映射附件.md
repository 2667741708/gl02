## 1. 目的和强制边界

本附件把 GL02 的现场数据、派生数据和 3D 对象建立为可追踪合同，解决以下问题：

1. 哪些画面来自实测，哪些来自插值、估算、模拟或工艺示意；
2. 115 个正式传感器节点、L7～L16 的 80 个炉体测温点和新增 18 个静压力点如何区分；
3. 料线、上料、炉次、出铁、铁水和炉渣化验在什么时间才能进入画面；
4. 单位、坐标、方位、数据质量和失联如何门禁；
5. 哪些映射允许，哪些映射会制造虚假炉况。

本附件不改变下列批准状态：

- 正式 GLB 继续保持 115 个 `SENSOR_<id>` 节点合同；
- 新增 18 个 A～F 静压力点第一期由 Three.js 动态创建，不先改写正式 GLB；
- P50 仍为 `KEEP_P50_PENDING_NOT_APPROVED`；
- P60 仍为 `not_granted_preflight_only`；
- 数据可访问不等于页面已经实时消费；未接入 `bf3d_snapshot/bf3d_event` 的数据不得宣称“已接线”；
- 本附件不授权写入生产数据库，也不包含任何口令、Token 或生产控制操作。

对应设计依据见[数据覆盖和运行边界](../高炉内部数据驱动3D动画总设计.md#4-数据源盘点与-3d-可用性)、[真实性与证据等级](../高炉内部数据驱动3D动画总设计.md#6-真实性与证据等级)和[统一时间合同](../高炉内部数据驱动3D动画总设计.md#7-统一时间炉次与事件合同)。

## 3. 统一语义包

### 3.1 三个正交维度

每条进入 3D 的数据必须同时携带 `evidence`、`derivation` 和 `quality`。三个字段不得互相替代。

#### Evidence：证据来源

| 值 | Visual Bible 标识 | 含义 |
|---|---|---|
| `measured` | `M` | 传感器实测、已核实事件或正式发布的离散化验 |
| `estimated` | `E` | 由有限实测、插值、质量平衡或软测量得出 |
| `simulated` | `S` | 由有版本、可复现的 CFD/DEM/过程模型得出 |
| `illustrative` | `C` | 仅用于解释机理，不代表当前炉况 |

空间插值不再伪装成第五种来源：六方位压力色带写作
`evidence=estimated + derivation=periodic_interpolation`，其原始 A～F 点仍为
`evidence=measured + derivation=raw`。

#### Derivation：生成方法

允许值：

```text
raw
validated_event
published_lab
aggregate
periodic_interpolation
bounded_vertical_interpolation
engineering_formula
state_estimate
scenario_lookup
manual_override
```

任何 `aggregate/interpolation/engineering_formula/state_estimate/scenario_lookup`
必须带 `method_id`、`method_version`、输入覆盖率和不确定度；不得只传最终值。

#### Quality：当前数据质量

与 Visual Bible 一致，至少支持：

```text
good | stale | bad | missing | manual | maintenance
```

同时必须携带：

```json
{
  "quality": {
    "state": "good",
    "reason_codes": [],
    "age_ms": 0,
    "expected_cadence_ms": null,
    "valid_range": null,
    "input_coverage": 1.0
  }
}
```

`0` 是合法数值时不得用作缺失标志；缺失一律使用 `null + quality.state=missing`。

### 3.2 七类时间

所有系统不得继续把跨源数据压成单一 `timestamp`。

| 字段 | 含义 | 主要对象 |
|---|---|---|
| `event_time` | 上料、开铁口、堵口等实际事件发生时间 | 上料、炉次、出铁 |
| `sample_time` | 传感器采样或化验取样时间 | 115 点、18 点、化验 |
| `judged_at` | 化验判定、审核完成时间 | 铁水/炉渣化验 |
| `published_at` | 结果正式可使用时间 | 铁水/炉渣化验 |
| `ingested_at` | 本地孪生系统接收时间 | 全部来源 |
| `render_time` | 当前 3D 画面表示的工艺时间 | 实时/回放统一时钟 |
| `knowledge_time` | “当时已知”回放允许使用的信息截止时间 | 历史回放 |

强制条件：

- 实时画面必须显示 `render_time` 和各来源 watermark；
- “当时已知”模式只允许 `published_at <= knowledge_time` 的化验；
- “事后分析”可以回挂后续化验，但必须显示“事后化验”；
- 迟到数据写入历史后必须通过 seek 重建，不能静默改写已经显示过的过去；
- 全部时间使用带时区的 ISO-8601；当前项目基准时区为 `Asia/Shanghai (+08:00)`，源系统无时区字段时必须在适配器记录解释规则。

## 7. 料线（`VB-DATA-104`）

| 字段 | 单位 | 当前语义 | 允许映射 | 门禁/禁止 |
|---|---|---|---|---|
| `L` | m | 已明确的主料线 | 水平料面整体升降、低料线和崩滑料事件 | 必须确认零点、正负方向、有效范围；不得解释成完整径向扫描 |
| `L_south` | m/待确认 | 南尺候选 | 对表通过后参与低阶倾斜面 | 当前源描述存在下限位/下极限位冲突，未确认前禁用 |
| `L_north` | m/待确认 | 北尺候选 | 对表通过后参与低阶倾斜面 | 当前源描述存在下限位/下极限位冲突，未确认前禁用 |

## 8. 上料和批次（`VB-DATA-105`）

### 8.1 字段

来源对象：`batch_input`。

```text
workdate
workdate2
lot
charge
value_01 ... value_24
value_sum
mining_batch_sum
coke_charge_sum
```

### 8.2 允许映射

- `charge` 区分矿批/焦批语义；
- 经单位确认的 `value_sum/mining_batch_sum/coke_charge_sum` 控制相对层厚或粒子数量；
- 经业务时间确认的事件触发 `BURDEN_CHARGE_STARTED/COMPLETED`；
- 炉顶短时粒子使用对象池/实例化，落料后合并为低模料层；
- 无堆密度、布料矩阵和真实截面积时，层厚只能显示相对值，不能标米。

### 8.3 门禁和禁止

- `workdate/workdate2/remark3` 必须确认分别是称量、闸门、皮带、料罐还是实际入炉时刻；
- 未确认前只能标“MES 批次事件”，不得标“炉顶落料瞬间”；
- `value_01...24` 是投料通道值，不得当成化学成分；
- 无粒径分布时不得把可视颗粒尺寸解释为真实矿焦粒度；
- 无溜槽角度、圈次和布料矩阵时不得生成有方向偏置的“真实布料”；
- 炉次的 `sumbatchstart/end` 未贯通前，不得强行宣称某批料归属于某炉次。

## 9. 炉次、出铁和生产实绩（`VB-DATA-106`）

| 来源 | 关键字段 | 允许映射 | 禁止 |
|---|---|---|---|
| `t_ipes_cond` | `meltno, opentime, closetime, tappingtime` | 炉次时间轴、开铁口、稳定出铁、收束和堵口事件 | 无瞬时流量时用流束粗细伪装实时流量 |
| `t_ipes_out_put` | `meltno, ironquan, grossweigh, tareweigh, weighttime` | 铁水计量、炉次结果、质量平衡输入 | 未明确罐/计量汇总规则时直接当每炉总铁量 |

经单位和汇总规则确认后，可用
`每炉铁量 ÷ 有效出铁时长` 生成 `estimated + engineering_formula`
的平均流量；必须与瞬时流量明确区分。

统一关联键优先使用 `meltno`，不得在已有炉次键时仅按“最近时间”匹配。

## 10. 铁水和炉渣化验（`VB-DATA-107`）

### 10.1 铁水质量

允许字段：

```text
C, Si, Mn, P, S, Ti, V, Cr, Cu, Ni, As
```

用途：

- `published_at` 后进入对应炉次结果卡；
- 历史回溯、模型标定和 C2 软测量目标；

当前完整命名视图与炉次关联尚未完全贯通，必须使用稳定的
`heatno/meltNo → batchno → 元素结果` 或受控 ETL；禁止只按最近时间猜炉次。

## 15. 失联、迟到和恢复（`VB-DATA-112`）

### 15.1 状态机

```text
missing
  └─ valid sample → good

good
  ├─ age > warn_after → stale
  ├─ source bad flag / range gate → bad
  └─ maintenance flag → maintenance

stale
  ├─ new valid sample → good
  └─ age > hard_expire_after → missing

bad / maintenance
  └─ source recovered + valid sample → good
```

### 15.2 行为

| 状态 | 数值 | 3D 对象 | UI |
|---|---|---|---|
| `good` | 使用 | 正常更新 | 显示采样时间 |
| `stale` | 保留最后值但禁止继续推断 | 冻结，降低数据覆盖层饱和度 | “数据陈旧”+最后时间 |
| `bad` | 不进入正常映射 | 保留点位，显示异常标识 | 原始质量码和原因 |
| `missing` | `null` | 隐藏数据形变/色带，保留空壳或点位 | “无数据” |
| `manual` | 可使用 | 必须显示人工标识 | 操作者、录入和有效期 |
| `maintenance` | 不参与诊断/插值 | 检修图标或隔离样式 | 检修区间 |

`warn_after/hard_expire_after` 必须按数据源写入受控配置。当前附件不虚构统一秒数；任何生产发布若仍没有按源阈值，状态为 `blocked`。

化验是炉次离散结果，不随墙钟自动变 `stale`；它的有效归属由炉次/样品和发布时间决定。
