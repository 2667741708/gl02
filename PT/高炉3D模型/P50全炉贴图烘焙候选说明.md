# P50 全炉贴图烘焙候选说明

## 目标与边界

P50 把已批准 P40 LookDev 中五段炉壳的程序材质转换为可供 glTF 交付继续处理的标准 Principled PBR 贴图材质。

- 对象：`HEARTH`、`BOSH`、`BELLY`、`SHAFT`、`THROAT` 五段炉壳。
- UV：沿炉体环向解析展开，五段共用一个非重叠图集和统一纹素密度。
- 通道：BaseColor、Roughness、Metallic、AO、OpenGL `+Y` Normal、ORM。
- ORM：`R=AO`、`G=Roughness`、`B=Metallic`、`A=1`。
- 保留：115 个传感器、其中 80 个炉体测温点，以及 P36 的 L7～L16 十层对象、父子关系、材质、矩阵和自定义属性。
- 不做：不覆盖生产 GLB，不声明 4K 批准，不执行 glTF Validator、KTX2、Meshopt 或浏览器性能验收；这些属于 P60。

## 实现入口

- [P50 Blender 主脚本](skills/bf3d-uv-bake/scripts/p50_full_furnace_bake_candidate.py#L741)：执行输入锁定、UV、烘焙、六通道审计、保留合同和候选保存。
- [共享环向图集](skills/bf3d-uv-bake/scripts/p50_full_furnace_bake_candidate.py#L291)：复用 P20 解析式展开，并把 10 个炉壳轮廓岛按统一米制比例重新打包。
- [单岛兼容处理](skills/bf3d-uv-bake/scripts/p50_full_furnace_bake_candidate.py#L148)：处理炉腹只有一个 UV 岛时 P20 最小间距集合为空的边界。
- [多对象累积烘焙](skills/bf3d-uv-bake/scripts/p50_full_furnace_bake_candidate.py#L534)：五段炉壳依次写入同一图集，不清除之前对象的像素。
- [ORM 打包](skills/bf3d-uv-bake/scripts/p50_full_furnace_bake_candidate.py#L612)：从独立 AO、Roughness、Metallic 图逐通道无损打包并验证最大误差。
- [标准 Principled 材质](skills/bf3d-uv-bake/scripts/p50_full_furnace_bake_candidate.py#L646)：材质中不保留 Noise、Voronoi 等程序纹理节点。
- [本机运行入口](run_p50_full_furnace_bake_candidate.py#L32)：默认锁定 P40 批准文件；若 Blender 未产生报告，即使 Blender 自身返回 0 也按失败退出。

## AO 决策

本次 smoke 使用中性开放炉壳 AO：

- UV 岛内部为 `1.0`，岛外为 `0.0`。
- 理由是当前炉壳是诊断可视化开放曲面；在未校准 cage/ray distance 前直接烘焙全场景 AO，容易把平台和附件的大阴影永久压入炉壳。
- 正式高分辨率阶段若需要真实局部 AO，应单独校准距离并与中性 AO 做 A/B 视觉审核，不能直接覆盖。

## 已发现并封闭的问题

1. P20 对单 UV 岛调用空集合 `min()`。P50 只恢复已经完成的单岛 UV 的报告元数据，不改 P20 文件。
2. PNG 保存后过早改成相对路径会让 Blender 在错误基准目录重载图片并释放像素，ORM 输入变成空数组。P50 现在在 BLEND 阶段保留烘焙源路径并把六图打包；P60 的 GLB 必须再验证无绝对路径。
3. Blender 发生 Python 异常时进程仍可能返回 0。runner 现在把“缺失 P50 报告”强制视为失败。
4. OptiX 无法写用户缓存目录时会把 `optix7cache.db` 放在当前工作目录；不影响本轮数值结果，但正式批处理前可配置可写缓存目录以减少警告。

## 下一门禁

P60 应从经过人工 UV 接缝和材质视觉审查后的 P50 候选复制交付集合，并完成：

1. 先导出未压缩 GLB。
2. glTF Validator 错误为 0，逐项解释警告。
3. 核对 115 个 `SENSOR_` 节点、L7～L16 十层、五个工艺段和 extras。
4. 确认 BaseColor 为 sRGB，Normal/ORM 为 Non-Color，Normal 为 OpenGL `+Y`，ORM 通道不串位。
5. 在 Three.js 正式查看器验证前后接缝、透明排序、测温点和十层动态高亮。
6. 未压缩基线通过后，再分别引入 Meshopt/KTX2，并执行高、中、低性能档测试。
