## 1. 目标与交付结论

本规划把“让 Codex 操作 Blender，把高炉做得更真实”改造成一条可中断、可回滚、可验收的工业资产生产线。目标不是生成一张好看的 Blender 截图，而是交付同时满足以下条件的高炉 GLB：

1. 炉壳具备哑光、微粗糙、风化钢质感；
2. 板缝、焊缝、法兰、紧固件和硬表面高光可信；
3. UV、纹素密度、PBR 通道和色彩空间可审计；
4. Blender Cycles/EEVEE 与 Three.js 最终页面方向一致；
5. 115 个传感器、L7～L16 分组、五个工艺段和世界坐标不被破坏；
6. L7～L16 十层点位筛选和动态高亮继续工作；
7. 高、中、低三档资源可在不同电脑浏览器中运行；
8. 每个阶段都有 `.blend` 检查点、机器报告、固定机位截图和回滚点。

本次已经完成项目本地 Skill 集合、上游 commit/SHA 锁定、来源说明和校验脚本；没有把 Skill 静默安装到用户全局目录，也没有安装、启动或授权任何 Blender MCP。

## 3. 当前模型真实基线

### 3.1 生成链路

当前高炉不是手工在 Three.js 中拼出来的，也不是一份权威施工 CAD 的无损转换。它由 YAML 参数驱动的 Python 生成器产生：

- [生成入口 generate_gl02_cad.py:L342](../../../pythonCAD/src/generate_gl02_cad.py#L342) 读取炉型、点位、出铁口和设备配置；
- [GLB 生成器 visual_glb.py:L472](../../../pythonCAD/src/geometry/visual_glb.py#L472) 生成浏览器模型；
- [STEP 生成器 build123d_shell.py（主装配第 118 行起）](../../../pythonCAD/src/geometry/build123d_shell.py) 生成 CAD 交换模型；
- [炉型坐标 furnace_profile.gl02.yaml:L3-L33](../../../pythonCAD/input/furnace_profile.gl02.yaml#L3-L33) 定义 Z-up/mm 到前端 Y-up/m 的关系；
- [传感器坐标转换 sensors.py:L60-L95](../../../pythonCAD/src/geometry/sensors.py#L60-L95) 使用前端坐标 `(x_m, height_m - 20, -y_m)`；
- 当前浏览器资产和 SHA 见 [gl02_blast_furnace.manifest.json](../../高炉前端数据/models/gl02_blast_furnace.manifest.json)。

`D:/文件/pythonCAD` 不是 Git 工作树，因此 [sources.lock.json](skills/sources.lock.json) 同时锁定了关键本地源文件、当前 GLB 和 manifest 的 SHA-256，避免只固定外部仓库却丢失真实生成基线。

### 3.2 当前结构

当前在用资产为 190 节点、29 网格、23 材质、115 个传感器，其中炉体温度点 80 个。五个工艺段和十个温度层已经分组；页面已开放 L7～L16，每层严格对应 A～H 八个炉体温度点。

### 3.3 当前专业贴图缺口

[visual_glb.py:L134-L155](../../../pythonCAD/src/geometry/visual_glb.py#L134-L155) 只写出 `POSITION` 和 `NORMAL`。当前 29 个 primitive 均无 `TEXCOORD_0`，GLB 中图片和贴图数量均为 0。因此：

- 页面挂载 `roughnessMap/bumpMap` 不代表专业贴图真正生效；
- 不补 UV 就不能可靠使用图片 PBR；
- 只有程序噪声和常量 `metalness/roughness` 会继续呈现“统一灰塑料”感；
- UV、烘焙和浏览器 GLB 回归必须是硬门禁，不是可选美化步骤。

## 6. Blender MCP 后端设计

### 6.1 首选原则

1. 先发现当前可用工具，不假设存在 `mcp__blender__*`。
2. 优先选择参数明确、返回结构化结果的 UV、Shader、Bake、Export 工具。

## 7. 不可破坏的模型合同

### 7.1 节点和分组

必须原名保留：

- 炉壳根 `APPROX_GL02_furnace_shell`；
- `APPROX_GL02_FURNACE_HEARTH/BOSH/BELLY/SHAFT/THROAT`；
- 115 个 `SENSOR_<id>`；
- `GL02_SENSOR_LAYER_L7`～`GL02_SENSOR_LAYER_L16`，每组 A～H 八点；
- 每个传感器 extras：`sensor_id/group/layer_id/height_m/sector/tag`；
- 传感器 scale `[0.115, 0.115, 0.115]`，不得在 Blender 中对传感器 Apply Transform。

### 7.2 物理点数量

- 炉体温度 80；炉喉温度 4；炉顶温度 4；炉顶压力 5；
- 料线 3；静压力 3；热风系统 9；过程诊断 5；出铁口 2；
- 静压点 `P_static_20m35/23m49/28m98`；
- 两个出铁口，禁止生成 `TAPHole_3`；
- 风口 26 个，当前标高 8.2 m；
- `T_top` 等派生量不得伪造成新的 `SENSOR_` 节点。

### 7.3 近似内部结构

料柱、矿焦层、软熔带、铁水池、渣层、煤气流线和风口回旋区是解释性近似结构。可以改善材质和可读性，但不得标注为实时真实料面或权威工程尺寸。

## 8. 硬表面几何提升

按 `$bf3d-geometry-audit` 执行：

1. 先灰模审计比例、轴向、原点、包围盒和受保护节点；
2. 修复翻面、非流形、零面积和异常缩放；
3. 对炉壳、加强圈、平台、管道和支撑分别设置小倒角与平滑规则；
4. 按参考图增加影响高光和轮廓的板缝、焊缝、法兰、螺栓和检修构件；
5. 高频细节进入法线贴图，避免浏览器几何爆炸；
6. 不移动传感器去适配新炉壳，发现间隙就形成待核报告；
7. 四向轮廓和 115 点坐标不变后才进入 UV。

## 9. UV 与贴图烘焙设计

### 9.1 UV

- 炉壳锥台使用环向展开，主纵缝放在背侧或真实接缝；
- 环板、法兰、管道、平台和支撑按几何类型独立设缝；
- 不能用一次 Smart UV 代替工业 UV 设计；
- 检查封闭曲面的正面、背面、侧壁、端盖和内壁；
- 高档源默认一个或两个 4K 图集，派生 2K/1K；浏览器不使用 UDIM；
- 同级纹素密度目标 ±15%，4K 岛间距默认至少 16 px；
- 方向性水痕、热影响和编号区域禁止镜像。

### 9.2 通道

| 通道 | 色彩空间 | 规则 |
|---|---|---|
| BaseColor | sRGB | 不烘入灯光和镜面 |
| Normal | Non-Color | OpenGL `+Y` |
| AO | Non-Color | 仅局部遮蔽 |
| Roughness | Non-Color | 表达钢/漆/锈/尘差异 |
| Metallic | Non-Color | 裸钢接近 1；漆锈尘接近 0 |
| ORM | Non-Color | R=AO、G=Roughness、B=Metallic |

先在一个炉壳段做小样，确认 cage、法线和浏览器方向，再展开整炉。

## 10. 哑光风化钢材质设计

材质不是全炉固定 `metalness=0.38`，而是由遮罩决定的五层体系：

1. 深灰绿基层钢或涂层；
2. 焊缝、板边、螺栓和积水处氧化锈蚀；
3. 平台下方、水平凸缘和凹槽积灰烟尘；
4. 从接缝、管口和平台边缘向下的低对比水痕；
5. 只在风口和出铁口等有依据区域出现的克制热变色。

裸钢金属度通常 0.85～1.0，涂层、锈和尘通常 0～0.1；主体粗糙度可从 0.58～0.82 校准，但必须由贴图产生空间变化。颜色变化要克制，主要质感来自粗糙度、法线和结构遮罩。

传感器、自发光点和动态环带必须保持独立，不进入炉壳材质图集。

## 11. 灯光、相机与渲染

建立两套灯光：

- `LOOKDEV_NEUTRAL`：中性 HDRI/大面积柔光、灰背景、无 Bloom，用于判断材质；
- `PRESENTATION_INDUSTRIAL`：柔和暖主光、冷轮廓光、克制环境光，用于展示。

锁定前、后、左、右四个全景相机，以及炉壳、风口、出铁口三个细节相机。每次迭代保持相机、灯光、曝光和色彩管理不变，只改一个变量。

有 RTX GPU 只代表可以尝试 Cycles GPU/OptiX；必须通过 Blender 设备信息证明实际启用，不能凭硬件型号推断。最终同时输出 Cycles 和 EEVEE/实时预览，以提前发现 Three.js 差异。

## 12. GLB 与 Three.js 交付

### 12.1 首阶段格式

当前项目 Three.js 为 r160，已有 GLTFLoader、OrbitControls 和 BufferGeometryUtils，但没有 KTX2、Draco、Meshopt 解码器。第一阶段必须先交付普通 glTF 2.0 GLB。只有补齐对应浏览器加载器和测试后，才能启用压缩扩展。

### 12.2 导出顺序

1. 从批准场景复制专用导出集合；
2. 烘焙程序材质并接到标准 Principled BSDF；
3. 导出未压缩 GLB 基线；
4. 验证节点、extras、坐标、AABB、材质和贴图；
5. glTF Validator 错误为 0；
6. 在 Three.js 正式查看器相同机位对照；
7. 基线通过后才单独测试 KTX2、Meshopt 或 Draco；
8. 生成带 SHA、数量、尺寸和版本的 manifest。

生效查看器是 [后置 CadFurnaceViewer:L9527](../../高炉前端数据/frontend_dashboard_v3.server.html#L9527)，分层控件在 [L10934](../../高炉前端数据/frontend_dashboard_v3.server.html#L10934)，高亮与哑光运行时覆盖在 [L10978](../../高炉前端数据/frontend_dashboard_v3.server.html#L10978)。实施时不能只改文件前部的旧定义。

### 12.3 配置唯一来源

层高、炉型剖面和工艺段边界目前在 YAML 与 HTML 中重复。正式实施应从 YAML 生成 `furnace_layers.json` 或扩展 model manifest，由 PythonCAD、Blender 验证和 Three.js 共用，避免三份硬编码漂移。

### 18.4 浏览器外观与内切面运行合同

Three.js 页面在默认“外观”模式下精确隐藏旧 GLB 中 45 个内部工艺装饰网格。炉壳保持不透明哑光，不再通过降低炉壳透明度来透视料柱、软熔带、气流、回旋区、滴落、铁水池或渣层；这样可以稳定保留 4K 粗糙度、法线、金属度和 AO 的表面层次。

用户切换到“内切面”后，查看器启用局部裁剪平面，并显示唯一权威的 `BF3D_INTERNAL_SIMULATION_RUNTIME`；旧 45 个圆环、竖线和装饰性流场在内切面中也继续保持隐藏，不再参与分阶段显现。料面、矿焦层、软熔带、风口喷煤、静压力、滴落和炉缸状态由统一控制器、统一时钟与证据门管理；没有合格数据时按 `illustrative/estimated/simulated` 边界降级或隐藏。塔架/桥、风口总管、煤气上升管/下降管、平台和支撑框架等外部遮挡仍可在内切面期间暂隐，剖切补光和边缘只服务结构阅读。状态栏固定显示证据边界，避免把参数化近似结构误解为现场实时测量。控制栏提供“外观、内切面、播放/暂停、复位”，并能与 L7～L16 单层八点筛选同时使用。

稳定运行接口挂在 `window.__BF_CAD_FURNACE_VIEWER`：

```javascript
setCutawayMode('exterior' | 'cutaway')
playCutaway()
pauseCutaway()
resetCutaway()
getCutawayState()
```

`.cad-furnace-viewer` 同步写入 `data-cutaway-mode`、`data-cutaway-phase`、`data-internal-count`、`data-internal-visible-count`、`data-cutaway-focus-count` 和 `data-cutaway-focus-hidden`，供页面状态和自动化读取。运行时复用内部材质副本与裁剪资源，不在每次切换时创建新资源；总览卸载时终止旧 RAF 并释放程序纹理/几何资源，再次返回总览会对新查看器重新初始化。OrbitControls 实例已纳入复位合同，复位同时恢复相机位置和旋转目标。`prefers-reduced-motion` 下保留剖面和颜色信息，但取消持续运动。

专项验证入口为 [verify_gl02_cutaway_runtime.cjs](../../tools/verify_gl02_cutaway_runtime.cjs)。它检查旧 45 个内部对象在外观和内切面均保持隐藏、权威仿真根只在内切面显示、5 组遮挡附件/补光/剖切边缘的启停、L7～L16 每层八点、PBR 通道保留、反复模式切换资源数量稳定、复位和路由往返重新挂载；正式模型与 P60 4K 隔离候选均已通过。Chromium 九个规定视口复跑为 9/9，[Firefox/WebKit 代表视口](../../logs/bf3d_cutaway_cross_engine_20260717/report.md)为 8/8；这仍不构成 P70 批准，现场 Edge、性能和实时数据链路仍按正式门禁补齐。

## 20. 炉内仿真与外部细颗粒建模专项总方案

专项方案解决了此前文档仍然偏薄的两个问题：

1. **炉内不再只有动画概念**

- L7～L16 十层、每层 A～H、115 个传感器和五段炉型的保护合同；
- 当前 P40/P50/P60 粗糙材质证据先做 `SURFACE_BASELINE_LOCK`，炉内工作不得覆盖；
- Blender 单炉壳段小样、炉内灰模、全炉材质、C1/C2/C3、Three.js 与跨浏览器的阶段顺序；
- UV/PBR、PMREM、各向异性、近看模式、高/中/低质量档位和错误回退；
- 固定机位、单通道图、24 帧旋转、近中远三距离和炉内逐层打开的视觉验收；
- 每个对象的 `source/time/confidence`、仿真 manifest、资产 SHA 和回滚边界。

### 24.3 布料对象和运行合同

R2N 的炉顶布料由以下固定资源组成：

1. `BF3D_ILL_CHUTE_AZIMUTH_PIVOT` 与 `BF3D_ILL_CHUTE_TILT_PIVOT` 控制溜槽方位和俯仰；槽底、侧壁和发射口随同一层级运动。
2. 矿石和焦炭分别使用固定容量 `InstancedMesh`；焦炭另有暗色孔隙细节实例，扬尘使用固定容量 `THREE.Points`。
3. 运动使用固定种子的解析重力、料面接触、一次碰撞和有界径向摩擦滚落。它是可解释的实时代理，不是 DEM、CFD 或现场粒径复现。
4. 12 个矿焦层槽位循环复用；`BURDEN_CHARGE_STARTED` 只启动落料，`BURDEN_CHARGE_COMPLETED` 才将新层沉积到料面，避免“颗粒尚未落地、料层先出现”的时间错误。
5. 事件必须通过 `schema_version=bf3d_event.v1`、`furnace_id=GL02`、运行模式、事件 ID/时间、矿焦类型和质量平衡门禁；重复 ID 在 256 项幂等窗口内拒绝。
6. `BF3D_ILL_COHESIVE_RESPONSE_WHAT_IF` 默认隐藏，只允许教学态显式打开；它是非因果 `illustrative` 响应，不继承 C2/C3 的 `estimated/simulated` 证据等级。
7. “布料聚焦”临时隐藏与炉顶落料无关的覆盖对象并移动相机；退出后恢复原相机、目标和可见性，不改模型资产。

### 24.4 性能和降级

- 高、中、低三档分别限制实例活跃数和扬尘活跃数；固定容量资源不随批次持续增长。

### 33.4 规划修正与下一顺序

R2W 中“完成当前 R2J 独立 AO UV/烘焙/显式绑定”的机器部分已经完成，但它没有修复

   命中、衰减幅度及量化；

   不改 BaseColor 来伪装 AO；
3. 若问题涉及内部层/横切面，先取得权威炉墙层栈或断面设计，再生成新版本结构候选；
4. 只有新的 1K AO 代表 off/on 出现可测局部信号且无黑环/整体压暗，才考虑完整矩阵；
5. 完整矩阵通过后仍需独立批准，才能讨论 2K 和重新进入 P50；P60/生产继续更后置。
