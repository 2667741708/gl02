## 已证实的根因与未证实项

- 普通问答受实时证据门禁和工具勾选影响，忽略“不查数据”；第一版已修复这些已测路径。
- 编码专用 Prompt 与新的产品目标冲突；第一版已关闭已测代码请求，同时保留数学与数据解释。
- 综合问题先取大量原始行，再反复规划，容易耗尽预算；确定性统计组合已降低已测查询数量。
- 工具成功后的收尾器只识别部分结果格式，导致有效快照被丢弃；第二版增加快照事实格式。
- 第一版模型综合发生异常且原逻辑吞掉异常，具体类型尚不清楚。第二版增加不包含输入内容的异常类型/HTTP 状态记录，并缩减综合上下文；是否解决必须在线验证。
- 仅改 Prompt 无法保证推断正确。对“正常”“显著”“因果”的结论必须检查是否具备相应阈值、检验或背景证据。

## 优化方案

1. **按缺少的信息决定查询。** 先形成问题清单：用户问什么、已有何种证据、缺什么。纯知识、用户给定数据、适用的历史工具证据直接回答；仅为缺项查询。
2. **证据统一表示。** 每项证据记录对象、时间/窗口、单位、来源、权限、质量、可支持的判断。事实与错误状态分离；失败不能覆盖成功事实。
3. **有限工具计划。** 常见统计和诊断各用一个有界只读组合。查询先验证对象，限制结果体积、调用次数和总耗时。预算结束在同一请求内完成一次收尾。
4. **答案逐项覆盖问题。** 输出已核实事实、条件性推断、尚缺信息。没有足够证据时澄清或明确只能回答哪部分，避免笼统拒绝整题。
5. **代码限制与分析能力分开。** 不暴露执行工具，限制代码生成；保留公式、比较、统计和中文方法说明。继续扩展伪代码、命令、变相请求和正常概念问题的正反例。
6. **持续回归。** 当前 32 条合成用例、11 个夹具；新增 QA-031/032 固化本轮功能介绍和无依据判断失败模式。每次修复先出现失败，再用同题同数据复测；保存模型、Prompt、程序和工具合同版本。
7. **以有效回答衡量质量。** 分别统计完全回答、部分回答、必要澄清、合理拒绝、错误回答及超时；按场景看成功率和长尾耗时。不能把 HTTP 200、非空答案或不编造等同于问题已解决。
