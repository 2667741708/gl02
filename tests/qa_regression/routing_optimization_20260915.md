## 四、目标路由：先明确需求，再选择证据与步骤

建议采用一个结构化请求计划，保留现有确定性查询工具。容易识别的问题走确定性路线；只有存在语义歧义或组合规划需要时，才用一次受schema约束的模型规划。仍只驻留当前批准模型，不为路由切换embedding/另一模型。

流程：

用户问题与有效多轮上下文 → 明确任务和禁止项 → 展开全部对象/时间窗/要求字段 → 检查已有证据 → 编排缺失查询 → 确定性计算 → 按子问题合成 → 字段与完成度校验 → 回复

计划至少包含：任务类型、子问题、对象、时间窗、基线、所需字段、证据来源、工具策略、步骤依赖、完成条件。解析器应保留原文跨度；A-D、南北、两铁口、多个气体成分要显式展开，不能只取首个匹配。

| 用户需求 | 应走路径 | 回复要求 |
|---|---|---|
| 普通知识/概念 | 无现场工具；涉及本厂规程再做keyword知识检索 | 直接解释，标明规程依据或一般知识 |
| 用户给定数据/假设 | 使用用户数据；需要复杂统计时使用批准的固定计算能力 | 标明输入属于假设；允许数学分析，禁止代码示例与执行 |
| 已有会话数据分析 | 校验owner、对象、时间窗、单位、质量和时效后复用 | 不因“分析”两个字重新查库；缺证据再补查询 |
| 当前值/历史值/统计 | 语义目录解析后批量只读查询 | 每个对象、每个窗口逐项返回或明确缺项 |
| “之前问过什么” | owner隔离的历史问答检索 | 不进入传感器查询，不能把本次测试污染当真实用户偏好 |
| 报表摘要 | 定位报表 → 读取对应正文 → 摘要 | 文件列表不是完成标志 |
| 综合炉况 | 权威诊断及时间 + 用户要求指标/窗口 + 必要规程 | 按子问题区分事实、条件性判断和缺项 |
| 代码/生产写操作 | 能力策略明确关闭 | 只拒绝该子请求；其余允许的数据分析继续完成 |

知识、只读数据查询和计算是不同的能力。不能要求所有问题都先查实时数据库，也不能把“禁代码”扩成“不能计算/不能分析”。

### 证据与执行设计

- **任务覆盖门禁**：例如三气体×一个时间窗要求三项；窗口对比要求两个窗口；日报摘要要求正文证据。完成率按需求项计算，不能用 tool.ok 或 answer非空判完成。
- **有类型的证据记录**：每项携带对象、值、单位、观测时间、来源、质量、计算输入/公式、是否旧快照；目录证据能回答“有哪些点位”，不能冒充当前数值。
- **固定工作流与跨源编排**：同服务优先批量；有依赖按顺序；不同服务且无依赖才并行。不要让模型把 components 数组传成JSON字符串或猜 account_profile。
- **成功事实独立保存**：已成功结果与MCP连接生命周期分离。后续工具或模型失败，仍给出已获得部分和具体缺项，保留一次无工具降级上限。
- **两类输出分开**：数据表、目录、图表元信息用程序生成中文输出；模型只写解释段。解释失败不会清空事实段，也不把原始JSON作为用户可见兜底。
- **校验字段关系**：按对象/单位/时间/来源核对每条断言，允许声明过的显示舍入和可复算结果；不要用全局数字集合比较。数值相同不代表指标相同。
- **限制信息输入与输出**：只注入当前问题所需且允许公开的字段。原始后台快照/隐藏上下文请求先执行权限与投影合同；正常表格、数学公式不按代码处理。
- **模型健康按需检查**：确定性目录/数据回答不应被模型未驻留全局阻断；需要模型的请求按有界排队/就绪流程处理，并记录准确阶段。不要自动重放已发送的SSE。
- **默认Prompt目标一致**：所有分支都保留“回答原问题、允许知识和数据判断、不编造、明示缺项、不生成/执行代码、不自动调控”。取消对所有综合问题统一250/350字的硬截断，按请求完成条件给足空间。

此处采用“明确路由 + 专用工作流 + 有界规划”的结构参考了[Anthropic的工作流设计说明](https://www.anthropic.com/engineering/building-effective-agents)；具体取舍来自本次本项目的失败证据，并不要求引入其模型或多智能体。

## 五、实施顺序与验收

### P0：先恢复正确回复与可信测量

1. 修复 JSON兜底与禁代码守卫冲突；仍关闭代码生成/执行。普通事实、表格和图链接不会被吞掉。

3. 测试集预检所有题后再启动：完整153目录识别PI/L/TFT等ID；结构化题与真正纯口语题分开；26行箭头/路径/助手说明保留后重分类。

### P1：补全需求驱动的路由

5. 任务类型优先于实体词；先确定历史问答、知识、报表、传感器或诊断。
6. 补全多对象、多窗口、基线与“列表→正文”依赖。以16条失败清单作为首批回归合同。
7. 把成功证据留在请求级记录中，明确工具失败、模型失败和答案失败；日志含request/step/stage/error_type和各阶段耗时，不含凭据。

### P2：综合问题与长尾可靠性

8. 基于缺失证据生成有界依赖计划；加入诊断时间和传感器时间的时效检查。
9. 以固定数据夹具验证计算与推理，再用新版本一次性线上复测。同题不同版本可以比较；旧版本失败不能偷偷重发覆盖。
