## 2. 总体路由策略

统一流程：

用户问题与有效上下文 → 任务计划 → 检查已有证据 → 补齐必要证据 → 固定计算与分析 → 按子问题回答 → 校验事实和完成度。

### 2.1 一个决策入口

在数据预取、知识检索、工具选择之前，产生唯一的结构化任务计划。各阶段使用同一计划，取消互相争抢的关键词判断。

计划至少包含：

- 用户要求做什么：解释、原文引用、查询、对比、分析、历史回忆、报表摘要等；可含多个子任务。
- 用户指令与引文的原文范围；文档名、岗位、章节路径、版本。
- 全部对象、全部时间窗、基线、单位、所需输出字段和时效要求。
- 已有证据、缺失证据、允许的来源/工具、步骤依赖、调用和耗时预算。
- 各子任务完成条件及允许终态：完整、部分、待澄清、依赖不可用、受限。

明确任务使用确定性解析；歧义/复杂组合可用一次受schema约束的规划，再由程序验证。关键歧义无法消除时只询问必要信息；不能猜测炉号、指标或日期。工具实际调度器必须执行允许列表，不能只在Prompt里要求模型遵守。

### 2.2 各类问题的明确路径

| 问题类型 | 证据和执行路径 | 不应发生的行为 |
|---|---|---|
| 一般概念与工艺解释 | 直接回答；涉及特定厂规时转文档检索 | 一律先查现场数据库 |
| 制度原文、章节规定 | 定位权威文档版本 → 章节正文/子章节 → 引用与完整性检查 | 用实时数值、历史聊天或一般常识冒充原文 |
| 用户给定数据分析 | 使用用户输入，必要时调用批准的固定计算函数 | 因“分析”强制查实时库；把假设写成实测 |
| 已有上下文分析 | 校验owner、对象、时间、单位、质量后复用；缺项再查 | 无条件重复查库，或把旧值当当前值 |
| 当前值、历史趋势、对比 | 对象目录解析 → 全对象/全窗口只读查询 → 固定统计 | 首个关键词命中后提前返回 |
| 历史问答 | 当前owner范围内的聊天检索 | 自动转查传感器；聊天内容当规程依据 |
| 报表摘要 | 定位报表 → 读取正文 → 提取关键结论 | 文件列表即宣告完成 |
| 综合问题 | 拆为多个子任务，合并共享查询，按依赖执行并汇总 | 一条工具结果代替全部问题 |
| 代码或生产写请求 | 拒绝受限子任务，其余允许部分继续 | 开放代码执行/代码示例，或误伤数学和数据分析 |

无工具是正常路径；已有充分证据时不调用外部工具。需要新数据才补查询，复杂计算使用已审核的固定函数，不启用任意代码执行。

### 2.3 综合问题的完成合同

示例“对比三种气体最近半小时与前半小时，并结合制度解释变化”应生成：

1. 三个对象 × 两个时间窗，共六项数据需求。
2. 时间对齐、缺测与单位检查；确定性计算差值/变化率，处理零分母。
3. 获取相应制度条款；没有正文时明确缺项。
4. 分别给出数据事实、比较结果、依据与条件性解释。
5. 每一项都完成或说明为何未完成；不得把相关性当因果或给出未经核实的操作结论。

完成度按需求项计算，不以tool.ok、答案非空或模型自评判定。保留各子任务状态，允许“有用且明确缺项”的部分回答。

## 3. 智能助手完善计划

### 3.1 知识库与原文能力

- 建立文档ID、版本、适用岗位、章节层级、正文、表格、来源位置的索引。保留现有keyword检索基线，先解决定位和正文完整性。
- 精确章节优先匹配；检索命中标题后展开父章节正文与所需子章节。长章节分段组织，不能任意截断后声称“全部规定”。
- 输出区分原文引用、原文归纳、一般解释；引用必须能定位到真实文档和章节。缺正文就明确不能核实，不补写制度。
- 知识答案只使用批准文档来源。聊天记录仅服务显式历史问答；回归测试会话、参考答案、审阅标准不进入知识证据。
- 将“同一指标出现在制度引文/实时查询/历史问答”做成成对回归，验证任务类型优先。

### 3.2 恢复统一Prompt目标

共用基础目标，分支只补充任务合同：

> 帮助用户完成高炉业务问答、规程解释和数据分析。直接回答原问题；已有充分信息时直接推理，必要时使用授权只读证据。区分实测、用户给定、文档规定与推断；不得编造来源或当前数值。逐项回应综合问题，说明缺项和不确定性。禁止生成代码示例、执行代码和修改生产设定；保留数学计算、统计分析和条件性判断。

维护实际能力清单，避免分支Prompt声称“只能查数据库”或“没有文档能力”。移除与任务完成冲突的统一短字数硬限制，按任务提供足够篇幅。

### 3.3 证据、计算与输出

- 请求级证据记录保存对象、值、单位、时间窗/观测时间、来源、质量及派生计算血缘；与MCP连接清理生命周期分离。
- 数值校验绑定对象/单位/时间/来源，支持已声明的显示舍入和单位换算；不采用全文数字集合判断。
- 固定函数覆盖均值、极值、差值、变化率、波动、时间对齐和缺测检查；使用合成夹具独立复算。
- 确定性事实表与模型解释分开生成。解释或后续工具失败仍保留已成功事实，明确尚缺什么。
- 禁代码检测识别代码意图及实际代码内容；中文表格、公式、图表链接不能触发整段替换。内部JSON不直接作为最终兜底答案。
- 限制注入的现场快照和工具清单范围，避免无关实时上下文干扰文档问答；保持公开字段投影和owner隔离。

### 3.4 多轮、工具运行与用户体验

- 多轮状态保存对象、时间窗、证据版本及用户约束；“再看前半小时”等追问继承必要范围，用户切换主题时清理不适用槽位。
- 工具参数由schema验证；优先复合只读/批量工具。有依赖顺序执行，无依赖且服务允许才并行。
- 工具健康、超时、参数错误、模型错误、生命周期清理错误分开记录；局部失败不清空全部结果。
- 保持既定恰好一次无工具最终降级；失败后提供已核实内容、缺项及可行下一步。不要盲目增加调用轮数。
- 确定性回复不依赖模型驻留；需要模型时按有界就绪/排队处理。不得因断线自动重发SSE。
- 页面展示处理中、完整、部分、待澄清、失败等真实状态；答案优先显示结论，再给依据和缺项。
- 脱敏记录request_id、计划版本、各阶段耗时、工具结果状态、证据覆盖和最终合同，能够定位失败阶段；不记录凭据和完整生产载荷。

## 5. 回归与发布门禁

### 回归集合结构

- 来源模板保留833行可追溯关系；知识独立题按818条计，15条重复来源单列复用。
- 非知识题独立报告；导入错误保留原记录并标oracle_invalid/重分类原因，不删除失败制造全绿。
- 维护路由、对象窗口、知识原文、给定数据、上下文复用、跨源分析、权限、代码边界、异常恢复等分组。
- 每个修复加入最小可失败夹具、口语变体和易混淆反例；保留未用于修复的持出题。
- 评测输入只包含问题及允许的证据。金标、测试标记和评审结论不能传给被测助手；隔离测试聊天检索污染。
- 自动核对调用、对象、数值、单位、来源和覆盖；独立审阅全部最终答案是否回答原问题、推断是否合理。非空不等于通过。
- 记录模型、Prompt、工具schema、代码及题集版本。固定夹具先比较V2与候选；线上动态数据不能直接拿不同时刻的数值差当算法改进。

### 发布目标（尚未达成）

1. 已确认缺陷及对应反例100%通过；正常非代码题误拒为0，代码生成/执行为0。
2. 全部要求项均有对应答案或明确缺项；原文题的文档、章节和引用可核实；无泛化内容冒充正式制度。
3. 实时数值无伪造；来源、单位、时间与对象对应；越权读取/生产写入/自动重放为0。
4. 工具或模型故障时保留有效事实；失败和恢复在固定夹具重复5次均满足合同。
5. 各类分别报告任务成功率、覆盖率、误用工具率、事实忠实度、延迟p50/p95和超时率；总体均分不能掩盖关键组退化。
6. 延迟目标在S0冻结后按任务类型设定，候选不得出现无解释的退化；目前不虚构统一秒数承诺。
7. 并发、取消、访客/操作员/管理员边界与长对话分别验收；未测项显式not_tested。

任意自然语言问题无法承诺100%正确。工程目标是：支持范围内可靠完成，证据不足时准确澄清/部分回答，受限请求明确说明，并且每次失败可定位、可复现、可加入回归。
